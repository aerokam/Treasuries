# 2.1 Assemble range data

**Specifies:** [2.1 Assemble range data](/knowledge/DFD_LEVEL3_YM_ASSEMBLE)
**Implemented by:** `YieldsMonitor/src/app.js#fetchOne`, `#fetchLive`, `#fetchArchiveFallback`, `#fetchHistory`, `#fetchAllHistory`
**Input:** the active [View Selections](../../knowledge/DATA_DICTIONARY.md#view-selections) (range, symbols, Custom start/end date), from the user; [Market Yields](../../knowledge/DATA_DICTIONARY.md#market-yields), from [CNBC GraphQL (E5)](../../knowledge/DATA_DICTIONARY.md#e5); [Yield history (S6)](../../knowledge/DataStores.md#s6); [Intraday archive (S18)](../../knowledge/DataStores.md#s18)
**Output:** [Yield Series](../../knowledge/DATA_DICTIONARY.md#yield-series) per symbol, to every other Yields Monitor process

For every symbol the user has checked, assembles that symbol's [Yield Series](../../knowledge/DATA_DICTIONARY.md#yield-series) over the active range, from whichever combination of a live CNBC read and a stored baseline the range calls for. Which combination that is depends only on the range, never on the symbol — the same four branches run for every symbol, TIPS and nominal Treasury alike.

<a id="assemble-2d-10d-range-data"></a>
## 2.1.1 Assemble 2D/10D range data

- Read the CNBC GraphQL provider range the UI range maps to: 2D to `1D`, 10D to `5D`.
- Fetch and cache the live bars for that provider range, keyed by symbol and provider range.
  - A cached result from an earlier fetch in the same session is reused unless the user asked for a fresh read.
  - Only a non-empty result is cached — a transient empty response is not, so it does not stay cached and block every later range switch from retrying.
  - If the active range is 2D: also fetch and cache the `5D` feed under its own key, for [Calculate day change (2.3)](./2.3_Calculate_Day_Change.md) to read.
- Filter the cached bars to the range's own cutoff (2 days back for 2D, 10 for 10D) and drop any bar dated a Saturday or Sunday.
- If the filtered result is not empty, that is the assembled series.
- If it is empty:
  - CNBC's feed returned genuinely nothing for this symbol and provider range — a real outage, not an off-hours quiet period; an empty response alone cannot distinguish the two.
  - Walk backward through the [Intraday archive (S18)](../../knowledge/DataStores.md#s18), one day at a time, up to fifteen days, for the most recent day whose own snapshot has the requested feed.
    - Use that day's own last bar even if it is a partial print rather than a full close: it is still the most recent real data available, and preferring an older but more complete-looking day in its place would make the display more stale, not more trustworthy, for a cosmetically nicer timestamp.
    - Read the "as of" time from the archive's own recorded fetch time, not from the last bar's own timestamp. CNBC's chart-bar feed can append one trailing element beyond the normal per-minute bars whose value is a genuine live quote but whose own timestamp field is mislabeled as the last real per-minute bar's time rather than when it was actually fetched — trusting that label would make a genuinely current fallback look far more stale than it is.
  - If no day in that lookback has the feed either, the assembled series is the empty result: the chart shows no data for the range.

<a id="assemble-1y-2y-3y-range-data"></a>
## 2.1.2 Assemble 1Y/2Y/3Y range data

- Reread CNBC's `6M` daily feed fresh on every load — the same feed regardless of which of 1Y, 2Y or 3Y is active — cached per symbol, not per range, since all three read the identical fetch.
  - The cache is depth-checked against the active range's own cutoff on every use, not reused blindly: a shallower fallback cached while the user was viewing 1Y or 2Y is retried against the deeper tiers below when the user switches to 3Y, so a symbol stuck on a shallow tier is not left silently truncated.
  - If the cached series does not reach back to the cutoff, or there is no cached series yet:
    - Fetch `6M` again.
    - If that returns nothing, fetch `3M` (a shallower daily-resolution tier of the same feed, reaching back about two years despite the name).
    - If that also returns nothing, fetch `1M` (reaching back about one year).
    - Replace the cache only with a result that reaches at least as far back as what is already cached — a shallower retry never regresses an already-cached deeper series.
- Filter the cached daily series to the cutoff and drop weekend-dated bars.
- Append the latest live point from a `5D` fetch on top of the filtered series regardless, past whatever the series' own last point is.
  - The cached daily tiers can be non-empty overall yet still miss their own most recent day — observed for one symbol whose `6M` tier had bars through months earlier then jumped straight to the current day, skipping the most recent trading day, while that same symbol's own `3M` tier did have it. The tier waterfall above only retries a shallower tier when the deeper one comes back completely empty, not merely missing its tail, so it would not have caught this. Appending the live point directly sidesteps needing to detect the gap tier by tier, and keeps the latest available point consistent across every range.
- If, after the `6M`/`3M`/`1M` waterfall, the daily series still does not reach back to the cutoff — a symbol-specific outage capped every tier short — fill the older gap from [Yield history (S6)](../../knowledge/DataStores.md#s6), up to the point the daily series' own earliest bar begins.
  - This store is weekly or quarterly resolution at this range, so the line goes coarser before that point rather than the range being truncated.

<a id="assemble-10y-all-range-data"></a>
## 2.1.3 Assemble 10Y/ALL range data

- Read [Yield history (S6)](../../knowledge/DataStores.md#s6), filtered to the range's own cutoff (10 years back for 10Y, 50 for ALL — a stand-in for the full history).
- Append the latest live point from a `5D` fetch on top, past the filtered series' own last point.
  - The once-daily baseline (refreshed weekdays at 17:00 ET) can lag behind what other ranges already show live, if that day's scheduled refresh has not yet run or failed for this symbol. Appending here keeps the latest available point consistent across every range; a symbol genuinely stale for longer than the live tip's own five-day reach still shows a real gap between its last baseline point and the live tip, rather than a fabricated bridge across it.

<a id="assemble-custom-range-data"></a>
## 2.1.4 Assemble Custom range data

- Read [Yield history (S6)](../../knowledge/DataStores.md#s6), filtered to `[ET midnight of the picked start date, ET midnight of the day after the picked end date)`, dropping weekend-dated bars.
- If the picked end date is within the past five days: fetch and cache the `5D` feed, and append every point later than the filtered series' own last point, subject to the same start-of-window floor as the filtered series itself.
  - The floor applies to the appended live points too, not only the stored history: without it, a symbol whose stored history has no point inside the picked window at all — the sparse 5-Year TIPS feed is the case this guards — could let a live point from before the picked start date leak into the series.

## Symbol reliability

The 5-Year TIPS feed is flaky: sparse and irregular bars, and a feed that can go missing for stretches none of the branches above are built to distinguish from a genuine gap. Every branch assembles it exactly the same way as any other symbol regardless — the flakiness is accounted for downstream instead, by never letting this symbol anchor a decision another symbol's snapshot depends on (see [Render yield curve snapshots (2.6)](./2.6_Render_Yield_Curve_Snapshots.md)'s anchor fallback). The 10-Year TIPS is the reliable reference wherever one is needed.

## Why the live tip is appended everywhere it can be

Three of the four branches above end the same way: whatever the baseline or waterfall produced, the most recent live point is appended on top of it. The persisted or reread baseline each branch otherwise reads is never guaranteed to be current to the minute — a daily refresh job runs once, a reread of CNBC's own daily tiers can still be missing today's bar — so appending the live tip directly is what keeps "the most recent point available" consistent across every range, rather than true only for the ranges that happen to read a live feed for their main series in the first place. The 2D/10D branch does not need this: it already reads a live intraday feed as its main series.
