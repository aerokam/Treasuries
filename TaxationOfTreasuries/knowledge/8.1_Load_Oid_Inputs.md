# 8.1 Load OID inputs

**Specifies:** [8.1 Load OID inputs](/knowledge/DFD_LEVEL2_TAXATIONOFTREASURIES)
**Implemented by:** `TaxationOfTreasuries/src/oid-calculator.js` (`loadInputs`), `shared/src/market-data.js` (`fetchTipsRefRows`, `fetchRefCpiRows`, `fetchMonthlyCpiNsa`)
**Input:** [TIPS reference data (S2)](../../knowledge/DATA_DICTIONARY.md#s2), [RefCPI (S3)](../../knowledge/DATA_DICTIONARY.md#s3) and [CPI (S8)](../../knowledge/DATA_DICTIONARY.md#s8)

Read the three stores the OID calculation needs. [Fetch TIPS reference data (1.6)](../../knowledge/1.6_Fetch_TIPS_Reference_Data.md) writes S2 and [Calculate daily Ref CPI (1.13)](../../knowledge/1.13_Calculate_Daily_Ref_CPI.md) writes S3 and [Fetch CPI (1.12)](../../knowledge/1.12_Fetch_CPI.md) writes S8.

<a id="data"></a>
When the OID Calculator is opened in the left pane, fetch both stores in parallel and build the rows:

- Read S2 with `fetchTipsRefRows()` as one row per TIPS of `cusip`, `maturity`, `datedDate`, `originalIssueDate`, `coupon` and `datedDateRefCpi`. Drop a row whose `datedDateRefCpi` is not a number or whose `originalIssueDate` is not a date.
- Read S3 with `fetchRefCpiRows()` as one row per calendar day, oldest first, of `date` and `refCpi`. S3 runs past the current date, because Treasury publishes the Ref CPI several weeks ahead.
- Read S8 with `fetchMonthlyCpiNsa()` as the NSA value of each month. When the read fails, calculate without it: the first of a month after the last date of S3 then has no Ref CPI.
- Show the status "Ref CPI from " and the first date of S3, " through " and the last date of S3.
- When either fetch fails, show the status "Load error: " and the reason, in red, and calculate nothing.
