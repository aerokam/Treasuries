# 8.2 Calculate TIPS OID

**Specifies:** [8.2 Calculate TIPS OID](/knowledge/DFD_LEVEL2_TAXATIONOFTREASURIES)
**Implemented by:** `shared/src/tips-oid.js` (`calculateTipsOid`, `tipsOutstandingInRange`, `rangeDatesOf`, `oidByCusip`), `shared/src/ref-cpi.js` (`lookupRefCpi`, `indexRatio`, `roundHalfUp`)
**Input:** the rows of [Load OID inputs (8.1)](./8.1_Load_Oid_Inputs.md); the [OID Calculator User Selections](../../knowledge/DATA_DICTIONARY.md#oid-calculator-user-selections) of [Render OID calculator (8.3)](./8.3_Render_Oid_Calculator.md)

Calculate the [OID](../../knowledge/DATA_DICTIONARY.md#oid) of one TIPS from a Start Date to an End Date, and the OID of the entries the user states for the TIPS outstanding in a range of dates.

<a id="oid"></a>
## OID

- Take the TIPS as the row of S2 whose `cusip` is the CUSIP.
- Set [Par](../../knowledge/DATA_DICTIONARY.md#par) to the Quantity × $1,000.
- Set the Start Date used to the [Original Issue Date](../../knowledge/DATA_DICTIONARY.md#original-issue-date) of the TIPS when the Start Date is before it, and to the Start Date otherwise. The issue date of a reopening is not used.
- Look up the [Ref CPI](../../knowledge/DATA_DICTIONARY.md#ref-cpi) of the Start Date used and of the End Date by the exact date, with `lookupRefCpi`.
- Set the [Index Ratio](../../knowledge/DATA_DICTIONARY.md#index-ratio) of each date to its Ref CPI divided by the Dated Date Ref CPI of the TIPS, with `indexRatio`. The Index Ratio Rounding gives one of two roundings for both dates:
  - Not rounded: the ratio as the division gives it.
  - Rounded as Treasury rounds it: truncated to six decimal places and then rounded to five, as [31 CFR 356 Appendix B](../../knowledge/31_CFR_356_Definitions_And_Formulas.md) states for the payments Treasury calculates.
- Set OID to Par × (Index Ratio of the End Date − Index Ratio of the Start Date used), rounded to cents. A negative OID is a deflation adjustment.

The calculation uses the End Date as entered, and the Start Date as entered except where the Original Issue Date replaces it. The [Start Date](../../knowledge/DATA_DICTIONARY.md#start-date) and [End Date](../../knowledge/DATA_DICTIONARY.md#end-date) entries state which date each case enters.

<a id="entries"></a>
## OID of the entries

The OID Range is a Start Date and an End Date, and there is any number of entries.

- The TIPS outstanding in the range are the rows of S2 whose Original Issue Date is before the End Date of the range and whose [Maturity Date](../../knowledge/DATA_DICTIONARY.md#maturity-date) is after the Start Date of the range, in order of Maturity Date, with `tipsOutstandingInRange`.
- An entry is an OID Entry. Several entries may have the same CUSIP, one for each acquisition.
- Until the user states others, the Start Date and End Date of an entry are those of the range, except that the Start Date is the Original Issue Date of the TIPS when the range starts before it, and the End Date is the Maturity Date of the TIPS when the End Date of the range is after it, and the user cannot change that End Date. `rangeDatesOf` gives these.
- Calculate the [OID](#oid) of an entry with the Quantity, Start Date and End Date of the entry. An entry whose inputs have a reason in [Inputs with no result](#invalid) has no OID and is not an entry.
- Order the entries by the Maturity Date of the TIPS, then the CUSIP, then the Start Date, then the order in which the user stated them.
- Set the subtotal OID of a CUSIP to the sum of the OID of its entries, in cents, and set the total OID to the sum of the OID of every entry. A CUSIP with one entry has no subtotal. `oidByCusip` gives the order, the subtotals and the total.

<a id="latest-ref-cpi"></a>
## Dates after the last Ref CPI

- For the first of a month after the last date of S3, take the Ref CPI as the NSA value of S8 for the month three months earlier, read as it is with no interpolation, as [31 CFR 356 Appendix B §I.B.3](../../knowledge/31_CFR_356_Definitions_And_Formulas.md) states for the first day of a month. January 1 takes October. `refCpiFromMonthly` of `shared/src/ref-cpi.js` reads it. The result states that month.
- Take the latest known Ref CPI as that of the first of the month three months after the latest month of S8, or that of the last date of S3 when that is later.
- When the End Date is after the last date of S3 and has no Ref CPI, calculate the OID at the latest known Ref CPI when the End Date is after it, and at the last date of S3 when it is not. The result states that date and that it replaces the End Date.
- When the Start Date used is after the latest known Ref CPI, there is no result.

<a id="invalid"></a>
## Inputs with no result

The calculation returns a reason, and [Render OID calculator (8.3)](./8.3_Render_Oid_Calculator.md) states it, when:

- no row of S2 has the CUSIP;
- the Quantity is not a whole number of 1 or more;
- a date is missing;
- the Start Date is after the End Date;
- the Start Date is after the [Maturity Date](../../knowledge/DATA_DICTIONARY.md#maturity-date) of the TIPS;
- the End Date is before the Original Issue Date of the TIPS;
- the End Date is after the Maturity Date;
- S3 has no Ref CPI for the Start Date used, or for an End Date inside the range of S3, and neither has the Ref CPI of the first of a month from S8.
