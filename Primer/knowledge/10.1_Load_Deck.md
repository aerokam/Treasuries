# 10.1 Load deck

**Specifies:** [10.1 Load deck](/knowledge/DFD_LEVEL2_PRIMER)
**Implemented by:** `Primer/src/deck-manager.js` (`loadDeck`, `parseDeck`, `parsePage`, `parseBlocks`)
**Input:** [Deck content](../../knowledge/DATA_DICTIONARY.md#deck-content), the file `Primer/content/deck.md`
**Output:** [Deck Pages](../../knowledge/DATA_DICTIONARY.md#deck-pages) to [Render deck pages (10.4)](./10.4_Render_Deck_Pages.md)

Fetch `content/deck.md` and parse it into pages. The deck holds the order, the chapter, the title and the text of every page, so reordering pages, retitling a chapter and changing a sentence need no change to the code. `index.html` holds no page text or order. [1.0 Primer](./1.0_Primer.md) states what the pages say.

<a id="content-driven-architecture"></a>
`content/deck.md` is the single file that defines both the deck's structure and its text — reordering pages, retitling a chapter and changing a sentence need no JavaScript edit. `index.html` has zero page-specific text or ordering in it; it fetches and parses this file at load time and builds the stage/TOC/dots from the result.

**Page syntax:**
```
# page-id
ch: Chapter Name
title: Page Title

<blocks...>
```
`page-id` fixes both the page's identity and its position — file order is deck order.

**Block syntax**, inside a page's body:
- `## Term` starts a definition card. If the body underneath contains `### CFR`, `### CFR-list`, or `### Notes` sub-headers (each field's text runs until the next `### ` sub-header or the next block), it renders as a full CFR/Notes review card. With no sub-headers, the heading's body is a simple content card.
- `### CFR-list` mirrors §356.5's own lettered/numbered outline.
- `:::lead`, `:::example`, `:::callout`, `:::aside` — fenced free-text blocks, each rendering as the matching styled element.
- `:::table` — a fenced pipe table.
- `:::card-table Term Name` — a table embedded inside a titled card.
- Citations: `[[356.5:§356.5(b)(1)(iv)]]` — the part before `:` is the eCFR URL key (see `CFR_URL` in `deck-manager.js`), the part after is the display label; renders as a linked, parenthesized citation.
- Inline formatting: `__underline__`, `**bold**`, `*italic*`, `` `code` ``. Raw HTML passes through untouched — this is trusted, hand-authored content, not user input.
