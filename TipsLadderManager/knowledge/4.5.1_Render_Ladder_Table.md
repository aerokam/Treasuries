# 4.5.1 Render ladder table

**Specifies:** [4.5.1 Render ladder table](/knowledge/DFD_LEVEL3_TLM_RENDER)
**Implemented by:** `index.html#renderBuildOutput`, `#renderOutput`, `#_renderBeforeStatePreview`, `render.js#renderTable`, `render.js#COLS`
**Input:** the [Build Result](../../knowledge/DATA_DICTIONARY.md#build-result) from [Build ladder (4.3)](./4.3_Build_Ladder.md), in Build and in Explore; the [Before-State Preview](../../knowledge/DATA_DICTIONARY.md#before-state-preview) and the [Rebalance Result](../../knowledge/DATA_DICTIONARY.md#rebalance-result) from [Rebalance ladder (4.4)](./4.4_Rebalance_Ladder.md), in Rebalance; [View Selections](../../knowledge/DATA_DICTIONARY.md#view-selections) from the user
**Output:** the [Ladder Table](../../knowledge/DATA_DICTIONARY.md#ladder-table) to the user, and to [Show drill popups (4.5.2)](./4.5.2_Show_Drill_Popups.md); the [Per-Year DARA](../../knowledge/DATA_DICTIONARY.md#per-year-dara) typed in a group header row, as [Ladder Parameters](../../knowledge/DATA_DICTIONARY.md#ladder-parameters), to [4.3.1](./4.3_Build_Ladder.md#resolve-per-year-dara) and [4.4.1](./4.4_Rebalance_Ladder.md#derive-per-year-dara-from-holdings-or-dara-plan)

Draw the [Ladder Table](../../knowledge/DATA_DICTIONARY.md#ladder-table) of the mode on screen:

- Draw every column from the one `COLS` array, filtered to the mode on screen: the columns of Build, or of Rebalance ([4.5.1 §Column Definitions](./4.5.1_Render_Ladder_Table.md#column-definitions)).
- Group the rows by funded year, and draw a header row above each group, with the aggregates of the group, the per-year DARA input, and the bracket-year excess flag ([4.5.1 §Funded Year Group Header Row](./4.5.1_Render_Ladder_Table.md#funded-year-group-header-row), [§DARA Input](./4.5.1_Render_Ladder_Table.md#dara-input), [§Aggregation rule](./4.5.1_Render_Ladder_Table.md#aggregation-rule), [§Bracket-Year Excess Flag](./4.5.1_Render_Ladder_Table.md#bracket-year-excess-flag)).
- Draw the Coupon Counting link on the header row of the settlement year, in Rebalance only.
- In Rebalance, draw the [Before-State Preview](../../knowledge/DATA_DICTIONARY.md#before-state-preview) as soon as holdings load, and the [Rebalance Result](../../knowledge/DATA_DICTIONARY.md#rebalance-result) after Run.
- Draw the totals row.
- Write the per-year DARA typed in a header row to the per-year DARA that 4.3.1 and 4.4.1 read, and recalculate the preview or an already-run Build from it.
- Expand and collapse a group by a click on its header row, and select the rungs of a range of rows ([3.0 §Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection)).

---

## Purpose

A single `COLS` array drives all table rendering for both Rebalance and Build modes.
Adding, removing, or changing a column requires editing one object in `COLS` only —
headers, cell values, sub-row values, totals, and popup wiring all derive from it.

**Before state on load (Rebalance):** Qty Before, Cost Before and Amount Before render when the holdings load, before Rebalance Ladder is clicked ([3.0 §Before-State Preview and Bracket-Year Excess Detection](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection), [6.0 §Before-State on Load](./6.0_UI_Layout.md)).

<a id="cols-schema"></a>
## COLS Schema

Each column is defined by one object:

```js
{
  label,        // string — label of the column
  headerHTML,   // string — header cell content; the two-row stacked headers are written here
  key,          // string — colKey used for popup routing and data binding
  fmt,          // 'str' | 'fy' | 'amt' | 'qty' | 'sgn' | 'yld' — formatting type
  rebalOnly,    // bool — column appears in Rebalance mode only (default false)
  buildOnly,    // bool — column appears in Build mode only (default false)
  fyLevel,      // bool — value is year-level, not per-TIPS (default false)
                //   group header: uses first row's value (not sum); null renders blank
                //   child TIPS rows: always blank (value is shown only in group header)
                //   excess sub-rows: unaffected (subValue still renders normally)
  value,        // fn(d, ri, details) → number|string — main row cell value
  subValue,     // fn(d, ri, details) → number|string | null — excess sub-row cell value (bracket rows only)
  total,        // bool — include in totals row (default false)
  totalFn,      // fn(d) → number — the row's contribution to the totals row (default: the main row value)
  drill,        // bool — cell is drillable (clickable popup) (default false)
  drillCond,    // fn(v, d) → bool | null — override drill condition (default: v != null && v !== 0)
  subDrillKey,  // string — colKey of the popup of the sub-row cell (default none)
  subDrillKeyFn,// fn(d) → string — as subDrillKey, chosen per row (Future 30Y cover or gap bracket)
  subDrillCond, // fn(sv, d) → bool — drill condition of the sub-row cell (default: sv != null)
}
```

`render.js` filters `COLS` by mode before rendering:
```js
const activeCols = COLS.filter(c => mode === 'rebal' ? !c.buildOnly : !c.rebalOnly);
```

### Shared columns (both modes)

| key | label | value | subValue | drill |
|---|---|---|---|---|
| `cusip` | CUSIP | `d.cusip` | `d.cusip` | — |
| `maturity` | DARA / Maturity | `d.maturityStr` | `d.maturityStr` | — |

**`saYield`** has `fmt: 'yld'` (`fmtCell`: `(v × 100).toFixed(3) + '%'`, as `yield` below). It is the [SA Yield](../../knowledge/DATA_DICTIONARY.md#sa-yield) of the TIPS, from [SA and SAO yields (S10)](../../knowledge/DATA_DICTIONARY.md#s10) joined to `tipsMarketData` by CUSIP, and it is the input of the SA-Yield order of the Within-Year Allocation Policy ([2.0 §Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy)). It renders in both modes. A TIPS with no row in that store has a blank cell, because `fmtCell` renders `null` as blank. The Mkt popup and the SA Yield fields of the drill popups show `—` for the same case (`drill.js`, `_showTipsRefModal` in `index.html`).

`COLS` has no funded-year column. The funded year is the **Group Header Row** ([Funded Year Group Header Row](#funded-year-group-header-row)), and `render.js` emits no funded-year `<td>` on a TIPS row.

**The header "DARA / Maturity".** On a TIPS row and an excess sub-row the cell shows `d.maturityStr`, which is not editable. On the group header row there is no cell at the Maturity position: that position is in the merged toggle cell of the header row ([Structure](#funded-year-group-header-row)), and the DARA input is in that cell, beside the funded-year label. The `<th>` is a two-row stacked header, as the CUSIP column has "Funded Year" over "CUSIP" (`headerHTML` of the `cusip` entry of `COLS`): row 1 is "DARA" and row 2, smaller and dimmed, is "Maturity".

<a id="sub-row-logic"></a>
## Sub-Row Logic

For bracket and Future 30Y cover rows, a sub-row is rendered showing excess quantities and cost. An excess sub-row shows no Amount: the Amount of a gap year or a Future 30Y year is on that year's group header row (2.0 §Amount of a Gap Year and a Future 30Y Year), in Build and in Rebalance, before and after, and is drillable. Sub-rows are labelled **"Gap"** for the gap brackets and **"Future 30Y"** for the Future 30Y cover pair.

**Row ordering:**
- Gap lower bracket: main row first, Gap sub-row second
- Gap upper bracket: Gap sub-row first, main row second
- Future 30Y lower cover: main row first, Future 30Y sub-row second (same as lower bracket)
- Future 30Y upper cover: main row first, Future 30Y sub-row second (same as lower bracket)

Both Future 30Y cover TIPS follow the lower-bracket pattern: excess sub-row always below the funded year row.

This ordering places gap coverage visually between the gap bracket rows, and Future 30Y coverage below each cover TIPS:
```
[gap lower bracket main]
[gap lower bracket — Gap sub-row]
... [non-bracket years] ...
[gap upper bracket — Gap sub-row]
[gap upper bracket main]
... [non-bracket years] ...
[Future 30Y lower cover main]   ← light blue
[Future 30Y lower cover — Future 30Y sub-row]  ← light yellow, label "Future 30Y"
... [years between the lower and upper cover] ...
[Future 30Y upper cover main]   ← light blue
[Future 30Y upper cover — Future 30Y sub-row]  ← light yellow, label "Future 30Y"
```

**Row identification:**
- Gap brackets: `d.excessQtyBefore > 0 || d.excessQtyAfter > 0` (rebalance) or `d.excessQty > 0` (build)
- Gap upper bracket: `d.fundedYear === summary.brackets.upperYear`
- Future 30Y cover TIPS: `d.fundedYear === summary.future30yUpperYear || d.fundedYear === summary.future30yLowerYear` when the ladder has Future 30Y years

**Retained bracket excess:** each retained maturity also gets a Gap sub-row, inserted oldest-first between the active lower bracket's Gap sub-row and the non-bracket rebalance years. The count is not fixed — render one per retained maturity present.

**Color coding:**
- `tr.bracket:not(.excess-subrow)` → light blue — gap bracket main rows and Future 30Y cover main rows
- `tr.excess-subrow` → light yellow — all excess sub-rows (Gap and Future 30Y); label distinguishes them

**Spec reference:** [3.0 §Target CUSIP resolution](./3.0_TIPS_Ladder_Rebalancing.md#target-cusip-resolution) (the funded need and the excess of a bracket year).

<a id="funded-year-group-header-row"></a>
## Funded Year Group Header Row

`render.js` groups the `details` array by `fundedYear` and emits one `<tr class="fy-group-header">` immediately above each group's TIPS rows. Group header rows appear in ascending funded-year order, including a bracket year that falls outside the ladder's First Year to Last Year range (a ladder over the gap years alone shows its lower bracket above the first gap year and its 2040 upper bracket below the last gap year).

### Structure

```
[▼/▶] [fundedYear label]  [DARA]  [agg col 3]  ...  [agg col N]
       ↑ one merged label cell (colspan=labelCount — CUSIP + Maturity + SA Yield
         positions in Rebalance, + Yield in Build)
```

- **Toggle cell** (`colspan=labelCount`, where `labelCount` is the count of the `str` and `yld` columns of the active, mode-filtered `COLS`: `cols.filter(c => c.fmt === 'str' || c.fmt === 'yld').length`, `render.js`): 3 in Rebalance (CUSIP, Maturity, SA Yield) and 4 in Build (CUSIP, Maturity, Yield, SA Yield). It contains the expand and collapse glyph (`▼` expanded, `▶` collapsed; none on a header row with no TIPS rows, such as a gap year or a Future 30Y year, where its width is kept so that the year labels align), the funded year integer, the suffix `(gap)` for a gap year or `(30Y)` for a Future 30Y year, the DARA input ([DARA Input](#dara-input)) and, on the settlement year in Rebalance, the Coupons link. A bracket year appends `*` (for example `2036*`) and its label carries the hover explainer. Left-aligned.
- **Numeric cells**: one per active numeric column (every column except CUSIP, Maturity, Yield, and SA Yield). Shows the group aggregate; see §Aggregation rule below. Excess/sub-row values are **excluded** from the header; excess rows remain visible as child rows with their own values.
- Bracket-year header gets class `bracket` in addition to `fy-group-header`.

<a id="dara-input"></a>
#### DARA Input

The group header row of a funded year is the only input of the per-year DARA, in Rebalance and in Build ([6.0 §Per-Year DARA (Table-Integrated)](./6.0_UI_Layout.md)). A compact number input is in the toggle cell, after the funded-year label (for example "▼ 2036  [DARA: 42,000]"), in no cell or column of its own. The "DARA" over "Maturity" header marks where the DARA of a header row is.

- The input reads from and commits to `_daraByYearStore` through `getDaraByYear()` and the persistence of [3.0 §Per-Year DARA (`daraByYear`)](./3.0_TIPS_Ladder_Rebalancing.md#per-year-dara-darabyyear), [§Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection) and §Persisting a DARA plan across sessions.
- It applies to every funded year, and not only to a flagged bracket candidate. For a year flagged by the [Before-State Preview](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection), entering a value also resolves the flag ([Bracket-Year Excess Flag](#bracket-year-excess-flag)).
- A gap year and a Future 30Y year have no TIPS row and get a group header row, and take their DARA input the same way.

<a id="coupon-counting-link"></a>
#### Coupon Counting link

In Rebalance, the settlement year's group header row — and only that row — additionally carries a
plain "Coupons" link (`.fy-rmd-link`), in the same merged toggle cell, immediately after the DARA
input (2.0 §Settlement-Year Coupon Treatment). No other year ever renders this link: the settlement
year is structurally the only funded year with both already-paid and not-yet-paid coupons in the same
calendar year, so it's the only row where the choice is ever meaningful. Build renders it nowhere at
all (`rmdOptionsLinkHTML` returns empty unless `mode === 'rebal'`): a Build has no already-paid half
to resolve, so it sizes at `'all'` with nothing to choose (2.0 §Settlement-Year Coupon Treatment
§Rebalance only). A trailing `*` on the link label (`Coupons*`)
marks a non-default choice, visible without opening the popover. The label is deliberately shorter
than the feature's name: it is in the settlement year's row of an already very wide table, and a
longer label widens that column. The popover title and the hover explainer both carry the full
"Coupon Counting" heading (`rmdOptionsTipHTML`, `src/render.js`), which is where the detail lives.

Clicking the link opens `#rmd-options-popover`, a single shared fixed-position popover (not a
per-row element, since at most one row ever shows the link) holding the three-way coupon-mode radio
group. Available cash is not here — it applies to the whole ladder, so it lives in Row 1 alongside
DARA (6.0 §Row 1). Committing a value (`change` on a radio) writes `_rmdCouponMode` and,
matching the DARA input's own commit rule, live-recomputes the pre-Run rebalance preview or an already-run Build; a post-run
Rebalance table only picks up the new value on the next Run. The link and popover are excluded from
the group header row's click-to-select/expand behavior (`.fy-rmd-link` alongside `.fy-dara-input`
and `td.drillable` in both the mousedown and click handlers) the same way those two already are.

The link itself carries `data-tip-html` — the same attribute the funded-year bracket label already
uses for its own hover explainer (§Funded Year Group Header Row above), so it's picked up by the
existing `mouseover`/`mouseout` delegation on `simpleEl`/`tableEl` and rendered in the same shared
`#bracket-tooltip` box with no separate hover mechanism or dedicated "?" affordance, matching how
the bracket label is both the content and the hover target. Hovering shows the explainer; clicking
still opens the popover — the two don't conflict, the same as any link that also carries a tooltip.

<a id="aggregation-rule"></a>
### Aggregation rule

Group header cell value depends on the column's `fyLevel` flag:

| Column type | `fyLevel` | Group header value |
|---|---|---|
| Year-level (`amtBefore`, `amtAfter`, `amount`) | `true` | First non-null value across groupRows; null (all rows null) renders as blank |
| Per-TIPS (`cost*`, `qty*`, `qtyDelta`, `cashDelta`, `cost`, `qty`) | `false` | `sum(col.value(d))` across all rows in group |

Year-level columns hold a single funded-year quantity (ARA Before/After, funded year amount). Summing would double-count when two TIPS share a funded year. The implementation scans groupRows for the first non-null value rather than always using `groupRows[0]`, because multi-TIPS funded years processed via reverse-loop + unshift may place a null-araBeforeTotal row first. If all rows are null (e.g., near-maturity TIPS), the header cell renders blank — not zero.

The `totalFn` (tfoot totals row) is unchanged — it still includes excess. Only the group header uses this narrower aggregate.

<a id="bracket-year-excess-flag"></a>
### Bracket-Year Excess Flag (Amber ⚠)

[3.0 §Before-State Preview and Bracket-Year Excess Detection](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection) flags the candidate years that stand off the curve fitted through the held years: at most one lower bracket candidate (the one with the highest excess), and the active lower bracket, the upper bracket (2040) and each Future 30Y cover independently. For a flagged year the split of the funded and excess portions is not known, so the preview shows a best guess at once:

- The DARA input of the flagged year ([DARA Input](#dara-input)) is pre-filled with the value of the curve at that year and carries the amber ⚠ marker "auto-set from the ladder's shape". `index.html` holds the flagged years in `_bracketAutoCapYears`, and `src/render.js#daraInputHTML` renders the marker and its tooltip.
- The `amtBefore` value of the group header row (`fyLevel`, [Aggregation rule](#aggregation-rule)) is the pre-filled value, and the Gap sub-row of the year shows the excess `raw ARA − that value`.
- The `qtyBefore` and `costBefore` values of the group header are split for a flagged year, and for no other year: `fundedYearQtyBefore = round((DARA − LMI) / piPerBond)`, `fundedYearCostBefore = fundedYearQtyBefore × costPerBond`, and the remainder `heldQty − fundedYearQtyBefore` (at least 0) and its cost are on the Gap sub-row beside the excess ([3.0](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection)). The funded row and the Gap sub-row then show one consistent split.
- When the holder edits the DARA input of the flagged year, the ⚠ clears and `amtBefore`, `qtyBefore` and `costBefore` (group header and Gap sub-row) are recalculated at once against the entered value, with the same LMI-based formula and no duration matching.

The flag is a preview display only. It does not change what Rebalance Ladder calculates ([3.0](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection), Scope: preview only).

### Child rows

All TIPS rows belonging to the group are emitted after the header with class `fy-child`. Excess sub-rows (`.excess-subrow`) are also `fy-child` rows — they are children of the same group and collapse/expand with it.

**`fyLevel` columns on child rows:** `amtBefore`, `amtAfter`, and `amount` render as blank `<td></td>` on all main TIPS child rows. The value is already shown in the group header. Excess sub-rows are unaffected — their `subValue` (excess dollar amount) still renders normally.

```html
<tr class="fy-group-header [bracket]" data-fy="2036" data-expanded="true">…</tr>
<tr class="fy-child bracket" data-ri="…">…</tr>          <!-- TIPS main row -->
<tr class="fy-child excess-subrow bracket" data-ri="…" data-sub="1">…</tr>  <!-- excess -->
```

### Expand/collapse behaviour

- **Default:** all groups expanded (`data-expanded="true"`).
- **Click on header row:** toggles `data-expanded` between `"true"` and `"false"`. All `.fy-child` rows with matching `data-fy` get `hidden` attribute set/cleared. **Exception:** if the clicked cell has class `drillable`, the click is treated as a drill action and does NOT toggle expand/collapse.
- **Expand All / Collapse All buttons:** set all group headers to the target state and show/hide all child rows accordingly.
- Expand/Collapse All buttons are placed in the form-card actions row (see 6.0 §Collapsible Groups).

### Drillable cells in group header rows

`fyLevel` columns that have `drill: true` emit a drillable cell in the group header row. The implementation finds the first non-null row in the group (along with its `ri`), checks `drillCond(value, d)`, and if true renders:

```html
<td class="drillable" data-row="<ri>" data-col="<colKey>" style="text-align:right">…</td>
```

The `data-row` attribute points to the `details[]` index for the non-null row, so the global drill click handler (`document.addEventListener('click', …)`) routes to the popup as it does for the drillable cells of a child row. When all rows in the group have a null value for the column, no drillable cell is emitted (a blank `<td>` instead).

A gap year and a Future 30Y year have no TIPS row. For an `fyLevel` Amount column, the group header row of such a year takes its value from `summary.syntheticYearAmounts` (`summary.syntheticYearAmountsBefore` for `amtBefore`) and emits `<td class="drillable" data-year="<year>" data-col="yearAmount|yearAmountBefore|yearAmountAfter">`, which routes by year and not by `details[]` index ([Popup Routing](./4.5.2_Show_Drill_Popups.md#popup-routing)).

### CSS classes summary

| Class | Applied to | Meaning |
|---|---|---|
| `fy-group-header` | `<tr>` | Funded year group header row |
| `fy-child` | `<tr>` | TIPS row or excess sub-row inside an expanded group |
| `fy-group-header.bracket` | `<tr>` | Group header for a bracket year |
| `drillable` | `<td>` | Cell that opens a drill popup on click; may appear in group header rows (fyLevel cols) or child rows |

**Spec reference:** 6.0 §Collapsible Groups for visual styling.

<a id="totals-row"></a>
## Totals Row

Only columns with `total: true` show values in the totals row, and others are blank. The CUSIP column shows "Total". A column total is the sum of `totalFn(d)` over the detail rows (by default the main row value plus the sub-row value). The Amount total also includes the Amount of each gap year and each Future 30Y year (`syntheticYearAmounts`).

**Spec reference:** totals are display-only sums, not spec-defined quantities.
