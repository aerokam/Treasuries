# 4.0 Computation Modules

## Dependencies
**Requires:** [TIPS Basics](../../knowledge/TIPS_Basics.md), [2.0 TIPS Ladders](./2.0_TIPS_Ladders.md), [3.0 TIPS Ladder Rebalancing](./3.0_TIPS_Ladder_Rebalancing.md)

This file specifies the module interfaces of the computation libraries: function contracts, input and output shapes, and the spec section that defines each formula. The math is defined in the files above.

---

## Purpose

Shared modules remove duplicated formula code between `rebalance-lib.js` and `build-lib.js`. Each function has one implementation, and both orchestrators import it. Every function maps to a spec formula. When a computed value is wrong, check the spec formula first, then the function.

## bond-math.js

`shared/src/bond-math.js` is the bond-math library of every app ([SharedModules §M3](../../knowledge/SharedModules.md#m3)). This section holds the contracts that TipsLadderManager uses. It has no ladder state and no running totals. The formulas are in [TIPS Basics](../../knowledge/TIPS_Basics.md).

### `bondCalcs(bond, refCPI)`

**Inputs:**
- `bond` — `{ price, coupon, datedDateRefCpi, maturity: Date }`. A missing `coupon` and a missing `price` are 0, and a missing `datedDateRefCpi` is `refCPI`, which gives an Index Ratio of 1.
- `refCPI` — number (the Ref CPI of the settlement date)

**Returns:**
```
{
  indexRatio,        // refCPI / bond.datedDateRefCpi, unrounded                       → DD Index Ratio
  paymentIndexRatio, // indexRatio truncated to 6 decimals, rounded to 5                → DD Inflation-Adjusted Principal
  principalPerBond,  // 1,000 × paymentIndexRatio                                      → DD Inflation-Adjusted Principal
  costPerBond,       // price/100 × indexRatio × 1,000                                 → DD Cost per TIPS
  nPeriods,          // 1 if the maturity month < 7, else 2                            → DD Last-Year Interest
  couponPerPeriod,   // bond.coupon / 2
  ownRungInt,        // principalPerBond × couponPerPeriod × nPeriods                  → DD Last-Year Interest
  piPerBond,         // principalPerBond + ownRungInt                                  → DD P+I per TIPS
  annualInt,         // principalPerBond × bond.coupon                                 → DD Annual Interest (Nominal)
}
```

`piPerBond` equals `principalPerBond × (1 + coupon/2 × nPeriods)`, which is `adjustedPrincipal + lastYearInterest`.

### `calculateDuration(settlement, maturity, coupon, yld)` → Macaulay Duration

Returns the Macaulay duration in **years**, or `null` when the inputs are degenerate.

**Convention:** Actual/Actual day count, semi-annual compounding (frequency = 2). It matches the Google Sheets `DURATION(settlement, maturity, coupon, yld, 2, 1)`.

**Guard conditions:**
- Returns `null` if `settlement >= maturity`.
- Returns `null` if `yld ≤ −2`, because `1 + yld/2` would be 0 or negative. Negative yields between −2 and 0 are valid.

**Algorithm:**

1. Find `nextCpn`, the first coupon date strictly after `settlement` (the semi-annual schedule aligned to the maturity month and day). A coupon payable on the settlement date is the seller's, so on a coupon date `lastCpn = settlement` and `DSC = E`.
2. Find `lastCpn`, which is `nextCpn` minus one semi-annual period.
3. Calculate the period variables:
   - `E   = days(lastCpn, nextCpn)` — the length of the current coupon period in days
   - `DSC = days(settlement, nextCpn)` — the days from settlement to the next coupon
   - `w   = DSC / E` — the fractional first period (0 < w ≤ 1)
4. Enumerate the coupon dates `nextCpn, nextCpn + 1 period, …` up to and including `maturity`. `N` is their count.
5. For each period index `j = 0, 1, …, N−1`:
   - `t_j  = w + j` — the time to payment, in semi-annual periods
   - `CF_j = coupon/2 × 1000` — the semi-annual cash flow per $1,000 face
   - The final period adds the principal: `CF_{N-1} = coupon/2 × 1000 + 1000`
   - `PV_j = CF_j / (1 + yld/2)^{t_j}`
6. Return `Σ(t_j × PV_j) / Σ(PV_j) / 2`. The final `/ 2` converts semi-annual periods to years.

**Used by:** `calculateMDuration`.

**Implementation:** `calculateDuration` returns `calculateDurationDetail(settlement, maturity, coupon, yld)?.macaulay ?? null`.

---

### `calculateDurationDetail(settlement, maturity, coupon, yld)` → Macaulay Duration workings

The one implementation of the algorithm above. `calculateDuration` and every synthetic-duration caller in `gap-math.js` (`gapParamsCore`, `future30yParamsCore`) take their number from this function. It returns `null` under the guard conditions of `calculateDuration`.

**Returns:**
```
{
  nextCpn, lastCpn,   // Date — the coupon-date pair the walk starts from
  E, DSC, w,          // day-count fractions (algorithm steps 2–3)
  periods,            // [{ date, t, cf, pv }] — one entry per coupon date (algorithm step 5)
  macaulay,           // Σ(t × PV) / Σ(PV) / 2 — the value calculateDuration returns
}
```

**Used by:** the nested (Level-3) drills `gapdur-<year>` and `f30dur-<year>` ([5.0 §Nested (Level-3) drills](./5.0_UI_Schema.md)), the only consumers that need the workings and not only the number.

---

### `calculateMDuration(settlement, maturity, coupon, yld)` → Modified Duration

```
mac = calculateDuration(settlement, maturity, coupon, yld)
return mac != null ? mac / (1 + yld/2) : null
```

**Spec reference:** [TIPS Basics §Duration](../../knowledge/TIPS_Basics.md) and §Yield Calculation Conventions. **Used by:** the durations of the Synthetic TIPS and of the brackets and covers (`gap-math.js`, `ladder-core.js`, `rebalance-lib.js`), and the weighted average duration ([Weighted Modified Duration](#weighted-modified-duration)).

---

### `couponSchedule(settle, maturity)` — coupon payment dates

```
nextCpn = first coupon date on or after settle (the schedule of calculateDuration)
dates   = [nextCpn, nextCpn + 1 period, …] up to and including maturity
```

**Returns:** an array of `Date`, earliest first, and `[]` when no coupon date exists on or before `maturity` (as `calculateDuration` guards). The last entry is `maturity`: the walk never passes it, and the principal is repaid the same day as the last coupon.

It uses `_nextCouponOnOrAfter`, the finder beneath `_nextCouponAfter` (which `calculateDuration`, `yieldFromPrice`, `priceFromYield` and `accruedInterest` use), so the payment dates of a held TIPS agree with its duration and yield calculations from the first coupon the buyer receives. The schedule keeps on-or-after because a payment dated the settlement date is still listed, and the duration and yield walks start at the coupon after it. **Used by:** [5.0 §Cash Flow Calendar](./5.0_UI_Schema.md) and `remainingCouponPaymentsThisYear` (`ladder-core.js`).

---

### `accruedInterest(coupon, settle, mature)` — day-count proration

```
nextCoupon, lastCoupon  // the semiannual schedule of calculateDuration; nextCoupon is the first coupon date strictly after settle, so on a coupon date lastCoupon = settle and A = 0
E   = days(lastCoupon, nextCoupon)   // days in the current coupon period
A   = days(lastCoupon, settle)       // days elapsed since the last coupon
accrued = (coupon/2 × 100) × (A / E) // per $100 par, nominal, with no Index Ratio applied
```

**Returns:** `{ accrued, A, E, lastCoupon, nextCoupon }`.

**Spec reference:** [Bond Basics §Accrued Interest](../../knowledge/Bond_Basics.md): Actual/Actual day count, the Treasury and broker settlement convention, and not a flat half-coupon. The function returns the general nominal formula. A TIPS caller applies the Index Ratio ([TIPS Basics §Accrued Interest](../../knowledge/TIPS_Basics.md)). It is the one accrued-interest implementation: `yieldFromPrice` and `priceFromYield` call it and share the coupon finder `_nextCouponAfter` with `calculateDuration`, and the Accrued Interest column of the Trade Ticket ([5.0 §Trade Ticket](./5.0_UI_Schema.md)) calls it directly. The dollars per bond of a TIPS are `accrued/100 × indexRatio × 1000`.

## gap-math.js

Gap year analysis and bracket sizing (`TipsLadderManager/src/gap-math.js`). The formulas are defined in [2.0 §Gap Years](./2.0_TIPS_Ladders.md#gap-years-section) and [2.0 §Duration Matching (Brackets)](./2.0_TIPS_Ladders.md#duration-matching-brackets).

### `interpolateYield(anchorBefore, anchorAfter, targetDate)`

Linear yield interpolation in maturity date between two anchor bonds.

```
yield = anchorBefore.yield +
        (targetDate - anchorBefore.maturity) × (anchorAfter.yield - anchorBefore.yield) /
        (anchorAfter.maturity - anchorBefore.maturity)
```

Returns `NaN` when an input is missing. **Spec reference:** [2.0 §Gap Parameter Calculation](./2.0_TIPS_Ladders.md#gap-parameter-calculation).

---

### `syntheticCoupon(yield)`

The eighth of a percent at or below the yield, and at least 0.125%. The coupon is counted in whole eighths:

```
syntheticCoupon = MAX(1, FLOOR(yield × 800 + 1e-9)) / 800
```

The tolerance `1e-9` is far below the precision of any quoted yield. Without it a yield that is an exact eighth loses one eighth to floating point (`0.03625 × 100 / 0.125` evaluates to `28.999999999999996`, so a plain `FLOOR` gave a coupon one eighth too low at 3.625% and at 7.25%). **Spec reference:** [2.0 §Synthetic TIPS for Gap Years](./2.0_TIPS_Ladders.md#synthetic-tips-for-gap-years).

`SYNTHETIC_INDEX_RATIO` is 1, the Index Ratio of every Synthetic TIPS ([Synthetic TIPS](../../knowledge/DATA_DICTIONARY.md#synthetic-tips)).

---

### `gapParamsCore({ gapYears, tipsMarketData, settlementDate, dara, daraByYear?, lmiAboveByYear?, pliCreditByGapYear? })`

The one gap-year sweep. For each gap year, longest to shortest: interpolate the yield, set the synthetic coupon, set the maturity (January 15), calculate the duration, size the quantity, and price the Synthetic TIPS. The sweep is [2.0 §Gap Parameter Calculation](./2.0_TIPS_Ladders.md#gap-parameter-calculation).

**Inputs:** `lmiAboveByYear` is `{ [year]: annual coupon dollars from the funded years above the gap }`. Build derives it from its preliminary sweep (`calcGapParams`, `ladder-core.js`), and Rebalance from the holdings and the targets (`calculateGapParameters`, `rebalance-lib.js`). These adapters are the only difference between Build and Rebalance, and both call `gapParamsCore`, so equal inputs give equal output and the Build, export, import and rebalance round trip is exact.

- When Pre-Ladder Interest or Available Cash zeroes a funded year, the adapter passes `annualInterest = 0` for that year, because a zeroed year buys no TIPS and gives no coupon to the LMI of a gap year.
- `pliCreditByGapYear` is `{ [year]: credit }`, the gap-year credits of the [Credit Pass](#pre-ladder-interest-option). It is empty without a credit.

**Returns:**
```
{
  avgDuration,  // cost-weighted mean of the Synthetic TIPS durations: Σ(cost·dur)/Σ cost (simple mean if Σ cost = 0) → 2.0 Average Gap Year Duration is Cost-Weighted
  totalCost,    // Σ cost over the gap years: the Gap Total Cost
  breakdown,    // per year: { year, qty, qtyExact, piPerBond, laterMatInt, pliCredit, dara, dur, synYld, synCpn, synPrice, indexRatio, costPerBond, cost, annualInt, durDetail }
  anchors,      // { before, after }: the two anchor bonds that interpolateYield used, each { maturity, yield }
}
```

With no gap years it returns `{ avgDuration: 0, totalCost: 0, breakdown: [] }`.

- `synYld`, `synCpn` and `durDetail` are the interpolated yield, the synthetic coupon derived from it, and the full Macaulay workings of `calculateDurationDetail`. They are carried for the Level-3 duration drill (`gapdur-<year>`, [5.0 §Nested (Level-3) drills](./5.0_UI_Schema.md)).
- `qtyExact` is `(dara − laterMatInt − pliCredit) ÷ piPerBond` before `qty` rounds it and floors it at 0. `annualInt` is `qty × 1000 × synCpn`, the annual interest of the Synthetic TIPS that every shorter year's `laterMatInt` includes. Both are carried so that the year rows of the Gap Dur popup ([5.0 §Quantity, cost and duration in one section](./5.0_UI_Schema.md)) show the figures the sweep used.
- `synPrice` is `priceFromYield(synYld, synCpn, settlementDate, maturity)`, or 100 when that is not defined. `indexRatio` is `SYNTHETIC_INDEX_RATIO`, and `costPerBond = 1000 × synPrice × indexRatio / 100`.

### `future30yParamsCore({ future30yYears, anchorBond, settlementDate, dara, daraByYear? })`

Pass 1 for the Future 30Y years ([2.0 §Future 30Y Rungs](./2.0_TIPS_Ladders.md#future-30y-rungs)). Every year is priced from one bond, `anchorBond`, the longest-dated issued TIPS, and not interpolated between two: `synYld` is `anchorBond.yield` for every year, and `synCpn` is `syntheticCoupon` of that yield. The maturity is February 15, and the quantity is `MAX(0, ROUND((dara − runningLMI) / piPerBond))`.

**Returns:** `{ avgDuration, future30yTotalCost, breakdown, future30ySeedLMI, anchorBond }`. Each `breakdown` entry carries the fields of `gapParamsCore`'s `breakdown` for the Future 30Y Dur popup (`f30dur-<year>`), with `laterMatInt` the running synthetic interest. With no years or no anchor it returns zeros and an empty `breakdown`.

### `bracketWeights(lowerDuration, upperDuration, avgGapDuration)`

```
rawLowerWeight = (upperDuration − avgGapDuration) / (upperDuration − lowerDuration)
lowerWeight = CLAMP(rawLowerWeight, 0, 1)
upperWeight = 1 − lowerWeight
```

The weights are shares of the total cost covered, so neither is below 0 or above 1. When `avgGapDuration` is outside `[lowerDuration, upperDuration]` (for example a deep-discount cover with a near-zero coupon has a longer duration than the average), the whole weight is held at the nearer cover and the duration match is not reached. When the two durations differ by less than 0.0001 the weights are 0.5 and 0.5.

**Returns:** `{ lowerWeight, upperWeight }`. **Spec reference:** [2.0 §2-Bracket Weights](./2.0_TIPS_Ladders.md#2-bracket-weights).

---

### `bracketWeightsN({ retained, dActive, dUpper, dGap, totalBlockCost, activeFloorWeight })`

The weights with [Retained Bracket Excess](../../knowledge/DATA_DICTIONARY.md#retained-bracket-excess). `retained` is an array of `{ duration, excessCost }`, oldest to newest. The retained maturities are fixed inputs and only the active lower bracket and the upper bracket are solved. `totalBlockCost` is the Gap Total Cost, and `activeFloorWeight` (default 0) is the share of it that the active lower bracket holds now. The formulas, the floor and the sale of the earliest retained maturity are in [2.0 §Retained Bracket Excess](./2.0_TIPS_Ladders.md#retained-bracket-excess).

**Returns:** `{ retainedWeights, activeWeight, upperWeight, feasible, reason, sold }`.

- `sold` is true when a retained weight was lowered.
- `feasible` is false when the inputs leave no solution that the holdings can reach: coincident durations, `dGap` outside the span, or an `activeFloorWeight` too high for even a fully sold retained side.
- `reason` names which one: `coincidentDurations`, `upperWeightNegative` or `activeBelowFloor`, and is `null` when feasible. Coincident durations report through `reason` even when the weights are inside their bounds, because the even split does not reproduce `dGap`.

Rebalance calls it for the Multi-bracket mode ([3.0 §Retained Maturities](./3.0_TIPS_Ladder_Rebalancing.md#retained-maturities-holdings-based)), and `simulatedRebalances` (`ladder-core.js`) calls it on each issue date with retained maturities. It supports any number of retained maturities.

---

### `bracketExcessQtys(totalCost, lowerWeight, upperWeight, lowerCostPerBond, upperCostPerBond)`

```
lowerExQty = ROUND(totalCost × lowerWeight / lowerCostPerBond)
upperExQty = ROUND(totalCost × upperWeight / upperCostPerBond)
```

A quantity is 0 where its cost per bond is not above 0. **Returns:** `{ lowerExQty, upperExQty }`. **Spec reference:** [2.0 §Excess Quantities](./2.0_TIPS_Ladders.md#excess-quantities).

## shape-math.js

The shape of a ladder and the maturity years that stand off it (`TipsLadderManager/src/shape-math.js`). It replaces the comparison of the raw ARA of a maturity year with one flat median, which charged every hump of the ladder to excess. The formulas are defined in [3.0 §Per-Year DARA from Portfolio](./3.0_TIPS_Ladder_Rebalancing.md#per-year-dara-from-portfolio) and [§Before-State Preview and Bracket-Year Excess Detection](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection).

### `smoothCurve(values, { width = 5 })`

A repeated running median of `width` (Tukey's repeated-median smoother, iterated until it stops changing), then one Hann pass. A running median is not pulled toward a spike, so the curve passes under the spike. The window cannot reach the first and last `(width−1)/2` points, so each end extrapolates the local slope outward: the median of the raw value and the linear extrapolation of the two nearest fitted points. A spike at the very end cannot become part of the curve. Below `width` points (default 5) it returns the input unchanged.

**Returns:** the fitted curve, of the length of `values`.

### `findSpikes(values, { width = 5, k = 4 })`

Every index that stands more than `k` robust scales (`1.4826 × median(|residual|)`, the median-absolute-deviation counterpart of a standard deviation) above `smoothCurve(values, { width })`. The spikes are found one at a time, strongest first, and each is flattened onto the curve before the next fit, because two adjacent spikes lift the curve between them enough to hide the smaller one.

**Returns:** `[{ index, value, curve, excess, z }]` in index order. `excess = value − curve` is the part of the year that stands above the shape of the ladder.

### `evenSpread(arr, spanCount)` / `MIN_SHAPE_POINTS`

`evenSpread` is the total of the values divided by `spanCount`, the number of rungs the inference assumes (and not the number of points), or `null` for an empty array or a span of 0. A held bracket year carries income that duration-matches coverage across the gap beside it, so two holdings around a 3-year gap (2036 and 2040 around 2037 to 2039) are five rungs of income, and dividing their total by 2 would let one bracket year borrow the number of the other.

`MIN_SHAPE_POINTS` is 5, the point count below which `smoothCurve` returns its input (its window covers the whole series), so that there is no shape to fit. Callers use `evenSpread` in that case.

### `inferShapeValue(years, values, targetYear, { width = 5 })`

The value implied for a year with no point in the series (a structural gap year, or a Future 30Y year after the last issued TIPS). It extends the local slope of `smoothCurve(values)` from the neighboring held year nearer to `targetYear`, and does not blend both sides, so a step in the shape of the ladder (for example the DARA falling once Social Security starts) is read as a step. A side gives a slope only with at least two held points on it. When neither side does it returns `null`, and the caller uses `evenSpread`.

**Used by:**
- `before-state-lib.js#detectBracketFlags`: `findSpikes` decides which bracket years and cover years are flagged as excess, and below `MIN_SHAPE_POINTS` held years a year is flagged when its raw ARA exceeds the `evenSpread` of the held years.
- `rebalance-lib.js#hasGapCoverageIntent` and `#derivePerYearDara`: `findSpikes` flags the bracket-candidate years and the signal at 2040, and `inferShapeValue` fills the gap-year DARA, in the recovery for a derived Per-Year DARA ([3.0 §Funding the rebalance](./3.0_TIPS_Ladder_Rebalancing.md#funding-the-rebalance)). Its low-data fallback flags a bracket-candidate year when its ARA exceeds 1.5 times the `evenSpread`.
- The file-load derivation in `index.html` ([3.0 §Per-Year DARA from Portfolio](./3.0_TIPS_Ladder_Rebalancing.md#per-year-dara-from-portfolio)) calls `inferShapeValue` and `evenSpread` for the gap-year and Future 30Y year fill, with `detectBracketFlags` for the candidate years.

## ladder-core.js — Credit Pass (Pre-Ladder Interest and Available Cash)

**Options of `sizeLadder`:** `preLadderInterest` (boolean, default `false`) and `availableCash` (dollars, default 0).

Two sources credit the earliest funded years, and one pass consumes them ([2.0 §Credit Pass](./2.0_TIPS_Ladders.md#credit-pass)):

- **Pre-Ladder Interest** ([2.0 §Pre-Ladder Interest](./2.0_TIPS_Ladders.md#pre-ladder-interest)): when `preLadderInterest` is on, `preLadderYears = MAX(0, firstYear − settlementYear)`. The Pre-Ladder Interest is the interest of the preliminary sweep for each of those years and the three amounts credited to them for the Future 30Y years and the gap years.
- **Available Cash** ([2.0 §Available Cash](./2.0_TIPS_Ladders.md#available-cash)): applied whenever it is non-zero, in Build and in Rebalance, whether or not the ladder starts in a later year and whether or not `preLadderInterest` is on.

The pass runs when `creditPool = availableCash + preLadderPool` is above 0. Available Cash is consumed first, and each year records the two parts separately so that the drill can show where the dollars came from.

- **Preliminary sweep** (`sizeLadder`, longest to shortest): produces `prelim[year]` with `targetFundedYearQty`, `annualInterest` and `laterMatInt` for every funded year. Its LMI is the full annual interest, and the credit pass uses the remaining-coupon LMI for the settlement year ([2.0 §Settlement-year LMI](./2.0_TIPS_Ladders.md#settlement-year-lmi)).
- **Effective preliminary sweep for the gap calculation**: `annualInterest` is 0 for every year in `zeroedFundedYears`, so the gap years' LMI is the interest of the TIPS that will be bought.
- **Final output** of the funded sweep for each funded year: `fundedYearQty = 0` for a zeroed year; for the partial-credit year `MAX(0, ROUND((DARA − laterMatInt − partialCredit − creditedInterest) / piPerBond))`; for every other year the same without `partialCredit`.
- The bracket `excessQty` is calculated as usual and added on top, whether or not the funded quantity of the year is zeroed, because duration matching applies to a bracket year with a funded quantity of 0.

**Summary fields:** `preLadderYears`, `preLadderPool`, `preLadderCouponPool`, `preLadderFuture30yPool`, `preLadderGapPool`, `preLadderNetCashPool`, `creditPool`, `zeroedFundedYears`, `partialCreditYear`, `partialCredit`, `pliCreditByGapYear`, `pliCreditByFundedYear`, `cashCreditByFundedYear`, `creditByFundedYear`.

## build-lib.js / rebalance-lib.js — Gap Year Simulated Outstanding TIPS

When the ladder has gap years, the interest of the Simulated Outstanding Future 10Y TIPS and of the Excess TIPS is income of the funded years before the first gap year. The definition, the issue dates, the rebalance at each issue date and the coupon counts are in [2.0 §Gap Year Simulated Outstanding TIPS](./2.0_TIPS_Ladders.md#gap-year-simulated-outstanding-tips). The computation is the one of the next section with the gap years, the bracket pair, the January 15 maturity and the January issue date in place of the Future 30Y years, the cover pair, the February 15 maturity and the February issue date.

**Computed once before the Phase 4 sweep**, after the duration match has fixed the Synthetic TIPS quantities, the bracket durations and the Excess TIPS quantities at settlement. For each funded year before the first gap year it gives three amounts: the interest from the Simulated Outstanding Future 10Y TIPS, the interest from the Excess TIPS, and the Net Cash of the issue dates in that year. Each is worked out for the year directly, and none is accumulated in the running LMI.

**Functions.** `gapIssueDate` gives each issue date, through `lastBusinessDayOfMonth` in `shared/src/settlement.js`. `gapRebalances` runs the rebalance at each issue date and returns the Excess TIPS after each and the Net Cash. It takes the lower bracket TIPS, the upper bracket TIPS and, with Retained Bracket Excess, the retained lower bracket maturities, each with the Excess TIPS it holds. `gapInterestByYear` returns the Simulated Outstanding Future 10Y TIPS interest, the Excess TIPS interest and the Net Cash credited to each funded year. `gapRebalances` and `future30yRebalances` are the two parameter sets of one engine (`simulatedRebalances` and `simulatedInterestByYear` in `ladder-core.js`), as are `gapInterestByYear` and `future30yInterestByYear`. `impliedGapInterest` (`rebalance-lib.js`) implies the Simulated Outstanding Future 10Y TIPS from the held Excess TIPS when a file has no DARA block.

**Sales expected.** On each issue date each bracket goes to the quantity that the duration match gives (`bracketWeights`): the Excess TIPS above it is sold, which is expected, and a bracket short of it buys the difference. With Retained Bracket Excess the retained maturities are never bought. They are held at what they hold, sold earliest first only as far as the match requires, and the active lower bracket is never sold to make room for them (`bracketWeightsN`). In a Rebalance, `runRebalance` passes the retained maturities to `sizeLadder` as `gapRetained`, which sizes the Excess TIPS at settlement around them.

**Funded-year quantity.** The quantity of a funded year is its DARA less the running LMI less the three amounts of the gap years and, when the ladder has Future 30Y years, the three amounts of the Future 30Y years, divided by P+I per TIPS, rounded to a whole number of TIPS and not below 0. The amounts are the same for a year in Build, in the Rebalance After state and in the Rebalance Before state, except that Before uses the quantities held before the first issue date ([3.0 §Build ≡ Rebalance "Before" and "After"](./3.0_TIPS_Ladder_Rebalancing.md)).

**Pre-Ladder Interest integration.** With `preLadderInterest` on, the Pre-Ladder Interest for the years before the first funded year includes these three amounts for those years, as the Future 30Y amounts are included in the next section. The quantity of a gap year depends on the pre-ladder credit it receives, and the Pre-Ladder Interest and the zeroing need depend on the gap amounts, which depend on the quantities. `sizeLadder` resolves this once, without iterating: the Pre-Ladder Interest and the need are sized from the gap amounts of a sizing that gives the gap years no pre-ladder credit, and the sizing that the sweep and the Amounts read is made again with the credit each gap year then receives. A fully pre-ladder-funded year is reconciled against its DARA in `fundedYearAmount`, so the difference between the two sizings does not reach an Amount.

## build-lib.js / rebalance-lib.js — Future 30Y Simulated Outstanding TIPS

When the ladder has Future 30Y years, the interest of the Simulated Outstanding Future 30Y TIPS and of the Cover Excess is income of the funded years before the first Future 30Y year. The definition, the issue dates, the rebalance at each issue date and the coupon counts are in [2.0 §Future 30Y Simulated Outstanding TIPS](./2.0_TIPS_Ladders.md#future-30y-simulated-outstanding-tips).

**Computed once before the Phase 4 sweep**, after the Future 30Y duration match has fixed the Synthetic TIPS quantities, the cover durations and the Cover Excess quantities at settlement. For each funded year before the first Future 30Y year it gives three amounts: the interest from the Simulated Outstanding Future 30Y TIPS, the interest from the Cover Excess, and the Net Cash of the issue dates in that year. Each is worked out for the year directly, because the coupon count differs from year to year, and neither is accumulated in the running LMI.

**Functions.** `selectFuture30yCovers` applies the cover rule. `future30yIssueDate` gives each issue date, through `lastBusinessDayOfMonth` in `shared/src/settlement.js`. `future30yRebalances` runs the rebalance at each issue date and returns the Cover Excess after each. `future30yInterestByYear` returns the simulated TIPS interest, the Cover Excess interest and the Net Cash credited to each funded year. `future30yLimit` derives the Maximum Future 30Y Rungs, and `maxLastYear` gives the ladder's last year at most. `syntheticYearAmounts` gives the Amount of each gap year and each Future 30Y year. `impliedFuture30yInterest` (`rebalance-lib.js`) implies the simulated TIPS from the held Cover Excess when a file has no DARA block.

**Funded-year quantity.** The quantity of a funded year is its DARA less the running LMI less these three amounts, divided by P+I per TIPS, rounded to a whole number of TIPS and not below 0. All three amounts are the same for a year in Build, in the Rebalance After state and in the Rebalance Before state, except that Before uses the quantities held before the first issue date ([3.0 §Build ≡ Rebalance "Before" and "After"](./3.0_TIPS_Ladder_Rebalancing.md)).

**Pre-Ladder Interest integration.** With `preLadderInterest` on, the Pre-Ladder Interest for the years before the first funded year is the coupon interest of the holdings plus these three amounts for those years. The Pre-Ladder Interest is stored as named parts, coupon interest, the interest of the simulated TIPS, the interest of the Cover Excess and the Net Cash, so the credit stays traceable in the Level-3 "Pre-Ladder Interest composition" drill (`buildPreLadderPoolDrill`). The need of a funded year for the zeroing condition is its DARA less its later-maturity interest and these three amounts, and not below 0.

**Rebalance years.** Every funded year credited with any of these amounts is in `rebalYearSet`, so the credits reduce the funded-year quantity and trigger selling, which prevents an Amount After above the DARA. The target-sizing `needed` subtracts the same three amounts, so a Build, export, import and rebalance round trip has zero trades through these years.

**PLI-zeroed year sell-all rule.** When Pre-Ladder Interest fully covers the funded need of a year, the target CUSIP quantity is set to 0 and all older TIPS in that year (when the portfolio holds several TIPS maturing the same year) are sold to 0. Otherwise those holdings remain and their principal and interest appear as income in the "Amount After" column of that year.

## allocation-policy.js

Within-year target and sell ordering of a Rebalance (`TipsLadderManager/src/allocation-policy.js`). The policies are defined in [2.0 §Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy), and the wiring into the per-year sweep is in [3.0 §Target CUSIP resolution](./3.0_TIPS_Ladder_Rebalancing.md#target-cusip-resolution). The functions are pure, with no ladder state and no I/O. The excess CUSIP of a bracket, gap or cover year never comes from here ([2.0 §Duration Matching (Brackets)](./2.0_TIPS_Ladders.md#duration-matching-brackets) and [§Retained Bracket Excess](./2.0_TIPS_Ladders.md#retained-bracket-excess) specify that identification). A bracket year that is also a funded year calls `rankForYear` for its funded need, with `policy` forced to `'maturity'` whatever the caller's `allocationPolicy` ([2.0 §Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy), Scope).

### `rankForYear({ candidates?, held?, piMap?, tipsMarketData?, policy?, rankOverride?, maturityPref? })`

**Inputs:**
- `candidates` — the `yearTipsListMap[year]` entries of the year (outstanding TIPS, driven by `maturityPref` and `yearOverrides`, [2.0 §Maturity Selection Within a Funded Year](./2.0_TIPS_Ladders.md#maturity-selection)).
- `held` — the current holdings of the year, which may include maturities no longer in `candidates`.
- `piMap` — `{ cusip → piPerBond }` for every held CUSIP (`'equal'` uses it to value each holding).
- `tipsMarketData` — `'saYield'` uses it to look up the SA yield of each candidate.
- `policy` — `'equal'` (default), `'maturity'` or `'saYield'`.
- `rankOverride` — an explicit `cusip[]`, highest priority first (the per-year override). When present it replaces the sort of the policy.
- `maturityPref` — `'last'` (default), `'first'`, `'semiannual'`, `'all'` or `'select'`. Only its direction (`'last'` or `'first'`) matters here, as the tie-break of the policies.

**Returns:** an array of `{ cusip, held }` over the union of `candidates` and `held`, highest buy and hold priority first. It does not change the quantities of `held`: the ranking decides order only, never whether a trade happens ([2.0 §Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy)) and never the direction of a trade, which the net change in the total of the year sets ([3.0 §Target CUSIP resolution](./3.0_TIPS_Ladder_Rebalancing.md#target-cusip-resolution), Direction of the trades of a funded year).

**`rankOverride`:** every override CUSIP in the union is placed first, in the order of the override. Any candidate or held CUSIP the override does not name (for example after `maturityPref` changed) is appended afterward in candidate order, so an override does not drop a CUSIP from consideration.

**`dir` (maturity tie-break direction):** `dir = maturityPref === 'first' ? -1 : 1`. `+1` sorts the latest-maturing first (the default, and the meaning of `'last'`) and `-1` the earliest first. It applies to the primary sort of `'maturity'`, to `'saYield'` when both SA yields are missing, and to `'equal'` when two candidates have the same held value.

**`'maturity'`:** `sort((a, b) => dir * (maturityOf(b) - maturityOf(a)))`.

**`'saYield'`:** sorts by `tipsMarketData.get(cusip).saYield`, highest first. A CUSIP with no SA yield ranks after one that has a value (`av == null → 1`, `bv == null → -1`). When both are missing, the maturity direction orders them. Equal SA yields keep their order in the union (candidates, then held).

**`'equal'`:** sorts by the current held value, lowest first, `(heldByCusip.get(cusip)?.qty ?? 0) × (piMap[cusip] ?? 0)`. A candidate not held has value 0 and ranks first. Equal values are ordered by the maturity direction. This ranking decides only which CUSIP is `rank[0]` in a run, and the levelling of the values over a trade is `levelValues`.

### `levelValues(values, needed)`

**Inputs:** `values` is `Map<cusip, currentPIValue>`, and `needed` is the target total P+I value of the set after the trade.

**Returns:** a new `Map<cusip, leveledPIValue>` that sums to `needed`.

Growth (`needed > Σ values`) is added to the member with the lowest value, and shrinkage is taken from the member with the highest value. Members tied at the extreme move together. The set is merged into groups of equal value: at each step the value of the extreme group moves toward the value of the next group, either using up the remaining amount on the way or reaching that group and merging into it, until the amount is used up or one group remains. The remainder then divides evenly over that last group.

`'maturity'` and `'saYield'` are fixed preference orders, so draining the least preferred CUSIP fully before the next is correct. `'equal'` has no fixed order and keeps the maturities near parity. Draining a shrinkage onto the CUSIP that ranked last at the start of the trade can pass parity and reverse which CUSIP is larger. With two maturities held at values 7 and 9 and a shrink to a total of 12, draining the 9-side to 5 leaves it below the 7-side. `levelValues` gives 6 and 6.

## ladder-core.js — Shared ladder sizing pipeline

`TipsLadderManager/src/ladder-core.js` is the one implementation of sizing the target ladder from a DARA ([SharedModules §M5](../../knowledge/SharedModules.md#m5)). `build-lib` and `rebalance-lib` both call `sizeLadder`. Neither re-implements funded sizing, the Pre-Ladder Interest credit, the gap and Future 30Y duration matching, or the corrected sweep. `rebalance-lib` reads the Future 30Y Pass 1 results from `sizeLadder`.

### `selectLadderBonds({ tipsMarketData, firstYear, lastYear, settlementDate, maturityPref?, couponPref?, yearOverrides?, excludeMaturingWithinMonths? })`

Picks the bond set from the TIPS market data alone: the funded-year TIPS list of each year (`selectYearTips` with `maturityPref` and `couponPref`, [2.0 §Maturity Selection Within a Funded Year](./2.0_TIPS_Ladders.md#maturity-selection)), the 2040 upper bracket, the active lower bracket (the most recently issued 10-year TIPS before the gap), and the Future 30Y cover pair ([2.0 §Future 30Y Cover Pair](./2.0_TIPS_Ladders.md#future-30y-cover-pair)). Returns `{ yearBondMap, yearTipsListMap, rangeYears, gapYears, future30yYears, future30yLowerYear, future30yUpperYear, future30yLowerCoverBond, future30yUpperCoverBond, future30yAnchorBond }`:

- `yearBondMap[year]` is the one representative TIPS, the latest of the list of the year. Every bracket, gap and cover path reads it, and it does not depend on `maturityPref` or `couponPref`.
- `yearTipsListMap[year]` is the ordered funded-year TIPS list (at least 1) that `sizeLadder` sizes.

This is the one source of which TIPS the target ladder holds, so Build and Rebalance size the same set. `couponPref` defaults to `'higher'`. Only `runBuild` passes a value, and `runRebalance` and `runFundedRebalance` pass none, so a Rebalance always uses `'higher'`.

- `yearOverrides` (Build and Rebalance, [2.0 §Picking Maturities for a Funded Year](./2.0_TIPS_Ladders.md#picking-maturities)) is a `Map<year, cusip[]>` that names the TIPS list of a year. It is resolved against the candidates of the year, sorted by maturity, and used in place of `selectYearTips` for each year in the map. An override whose CUSIPs do not resolve is ignored, so `yearBondMap`, `gapYears` and `future30yYears` stay correct for a year that the picker has set to a DARA of 0. The caller sets that DARA to 0 (`_runBuildFromForm` in `index.html`): `selectLadderBonds` and `sizeLadder` have no unfunded-year concept beyond `daraByYear`.
- `excludeMaturingWithinMonths` (Build only; Rebalance passes 0) removes from the candidates a TIPS that matures no later than that many months after the settlement date ([DD §5.1](../../knowledge/DATA_DICTIONARY.md#5.1-issuance-dependent-values)).

### `sizeYearRungs(list, need, refCPI)` / `aggregateRungs(rungs)`

Splits the real P+I `need` of a funded year across its ordered TIPS `list` by allocation weight (equal today), each TIPS sized from its P+I. The latest maturity takes the rounding remainder ([2.0 §Multi-TIPS Funded-Year Split](./2.0_TIPS_Ladders.md#multi-tips-funded-year-split)). Returns `[{ bond, ir, pir, pi, coupon, qty }]`, earliest to latest, with `ir` the unrounded Index Ratio and `pir` the Index Ratio under Treasury's rule. `aggregateRungs` returns `{ qty, annualInterest, piTotal }`: the funded quantity, the real annual coupon for LMI (`qty × 1000 × pir × coupon`), and the real P+I delivered.

### `sizeFuture30yCover({ future30yYears, future30yLowerCoverBond, future30yUpperCoverBond, future30yAnchorBond?, settlementDate, dara, daraByYear?, refCPI })`

The Future 30Y half of duration matching ([2.0 §Duration Matching (Brackets)](./2.0_TIPS_Ladders.md#duration-matching-brackets), [§Future 30Y Rungs](./2.0_TIPS_Ladders.md#future-30y-rungs)): `future30yParamsCore`, then the cover durations, `bracketWeights` and `bracketExcessQtys`. It is a separate function because `rebalance-lib` needs the cover excess quantity (for the simulated TIPS interest and the Cover Excess interest) before the rest of `sizeLadder` runs. `sizeLadder` calls it too, so Build and Rebalance run the same clamped duration match. With no Future 30Y years it returns zeros and nulls.

Returns `{ future30yParams, future30yLowerDuration, future30yUpperDuration, future30yLowerWeight, future30yUpperWeight, future30yLowerExQty, future30yUpperExQty, future30yFellBack, future30yCoverReason, future30yTotalExcessCost, future30yLowerMonth, future30yUpperMonth }`. `future30yFellBack` is true when the average duration is outside the span of the cover durations, and `future30yCoverReason` is then `'aboveUpper'` or `'belowLower'`.

### `sizeLadder({ dara, daraByYear?, firstYear, lastYear, optionalYears?, rangeYears, gapYears, future30yYears, yearBondMap, yearTipsListMap?, tipsMarketData, refCPI, settlementDate, settlementYear, preLadderInterest?, bondHolidays?, availableCash?, rmdCouponMode?, tradeDate?, gapRetained?, <Future 30Y cover bonds and years> })`

A pure function from the per-year DARA and the bonds to the target ladder. It runs, in order:

1. The preliminary sweep (the pre-ladder bucket and the gap-LMI estimate, through `sizeYearRungs` and `aggregateRungs`), and the check that every funded year funds a bond, except the `optionalYears` of a Rebalance ([3.0 §Intentional empty rungs](./3.0_TIPS_Ladder_Rebalancing.md#intentional-empty-rungs-and-the-rung-validation-waiver)).
2. The Future 30Y duration match and Cover Excess, and the Simulated Outstanding Future 30Y TIPS and Cover Excess interest ([2.0 §Future 30Y Simulated Outstanding TIPS](./2.0_TIPS_Ladders.md#future-30y-simulated-outstanding-tips)).
3. The gap stage and the credit pass ([Credit Pass](#pre-ladder-interest-option)), then the gap stage again with the credits.
4. The corrected funded sweep, longest to shortest ([2.0 §Algorithm](./2.0_TIPS_Ladders.md#algorithm-longest-to-shortest-sweep)).

`yearTipsListMap` is optional: without it each year falls back to its one `yearBondMap[year]` TIPS.

Returns the target quantities and the parameter and Pre-Ladder Interest fields that callers show: `prelim`, `corrFYQty`, `corrLMI`, `corrRungs` (`{ [year]: rungs[] }`, the sized sub-rungs per year, which `build-lib.js` uses to emit one `results` and `details` row per sub-rung), `zeroedFundedYears`, `partialCreditYear`, `partialCredit`, the credit fields of the Credit Pass, `gapParams`, `lowerYear`, `upperYear`, the bracket weights, durations and excess quantities, `future30yParams` and the Future 30Y fields, the rebalances and the interest by year of the gap years and the Future 30Y years.

**One source for Build and Rebalance.** A Build, export, import and rebalance round trip (the CUSIP and quantity output of the Build is the holdings, with the same DARA, first year and last year) has zero trades and zero net cash. Rebalance derives the per-year DARA from the portfolio, calls `sizeLadder`, and diffs the result against the holdings into buys and sells. The holdings do not enter the sizing, and only the DARA does.

**Adapters call shared cores.** `calcGapParams` (`ladder-core.js`; the LMI above the gap is the preliminary coupon) and `calculateGapParameters` (`rebalance-lib.js`; the LMI from the actual holdings and the Future 30Y cover) are holdings and preliminary adapters, and both call `gapParamsCore` of `gap-math.js`. The gap sweep is defined once.

## Weighted Modified Duration

`build-lib.js` and `rebalance-lib.js` both calculate `weightedAvgDuration` (the portfolio weighted modified duration) and return it in `summary`.

**Formula:**
```
weightedAvgDuration = Σ(mv_i × mDuration_i) / Σ(mv_i)
```

- `mv_i = totQty_i × costPerBond_i` (Build: `fundedYearQty + excessQty`. Rebalance: `qtyAfter`, which for a bracket row is `fyQty + excessQtyAfter`)
- `mDuration_i = calculateMDuration(settlementDate, bond.maturity, bond.coupon, bond.yield)`, called with the arguments of every other duration call
- The sum runs over all TIPS rows in `details`

**Implementation:** `mDuration` is calculated per detail row while the details are built, and stored on the detail object. `weightedAvgDuration` is derived from the details array after the loop (`calcMktWtdAvg`, `bond-math.js`: a null value adds 0 to the numerator and its market value still counts in the denominator).

**Display:** `#wad-display` (label *Avg Mod Dur*), `#avg-yld-display` (*Avg Yld*) and `#avg-sa-yld-display` (*Avg SA Yld*) in `#ladder-stats-display`, shown after a run in both modes ([6.0 §Row 4](./6.0_UI_Layout.md)). Modified duration has no unit suffix, and a yield is shown as a percentage (for example `2.15%`).

**`weightedAvgYield` and `weightedAvgSaYield`:**
```
weightedAvgYield   = Σ(mv_i × yield_i)   / Σ(mv_i)
weightedAvgSaYield = Σ(mv_i × saYield_i) / Σ(mv_i)
```

They use the weights of `weightedAvgDuration`. `yield_i` is `d.yield` (the real yield of the market data), and `saYield_i` is `d.saYield`, which can be `null` for a holding. Both are stored on each detail row and are in the `summary` of `build-lib.js` and of `rebalance-lib.js`.

### Weighted-Average Popups (Avg Mod Dur / Avg Yld / Avg SA Yld)

Clicking one of the three labels opens a popup (`_weightedAvgPopupRows`, wrapped by `buildWeightedDurationPopupRows`, `buildWeightedYieldPopupRows` and `buildWeightedSaYieldPopupRows` in `drill.js`). It lists every detail row with `mktValue > 0`: the funded year and CUSIP, the maturity and market value, and the value of the row (modified duration, yield or SA yield), then a total row `Σ(MV × value) ÷ total MV`. `mktValue` is set once, with `mDuration`, `yield` and `saYield`, in the pass that calculates the three weighted averages: `(fundedYearQty + excessQty) × costPerBond` in `build-lib.js` and `qtyAfter × costPerBond` in `rebalance-lib.js`. A popup cannot differ from its displayed figure.
