## Form Card Layout

Five stacked rows inside `.form-card`, grouped by what the holder sets: what to build, how to build it, and the actions on the result. The DARA of a range of rungs is set by selecting the rungs on the ladder table ([3.0 §Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection)).

### Row 1 — Import/Export + Ladder target (`.card-inputs`)
Flexbox, `gap: 8px 20px`, `align-items: flex-end`.  
Contains, in order: **Import** and **Export** (`#import-menu-btn` and `#export-menu-btn`, [Import/Export Menus](#import-export-menus)) side by side at the far left, then DARA, First Year (in Build the default is the Default First Year, [DD §5.1](../../knowledge/DATA_DICTIONARY.md#5.1-issuance-dependent-values)), Last Year, and Available cash (`#available-cash`, dollars, [2.0 §Available Cash](./2.0_TIPS_Ladders.md#available-cash)). The First Year and Last Year fields of the current mode are shown. Available cash is in Rebalance only. It has a `?` help button and, when the app has filled it in from the coupons already received, an amber ⚠ beside its label and an amber border on the input. Both clear when the user types a figure.

Available cash is in Row 1 because it is a figure that the ladder targets, and not a policy that governs how the ladder is constructed.

The card has no yield-source control. The source of the market data is a constant in `shared/src/market-data.js` ([3.1 §4.0 Yield Sources](./3.1_Data_Pipeline.md)).

### Row 2 — Construction/computation policy (`.card-inputs`, `margin-top: 8px`)
Contains: Brackets (`#bracket-mode`, rebalance-only — 2-bracket / Multi-bracket, with its own "?" help
button), Pre-ladder int., Maturity preference (`#build-maturity`, 2.0 §Maturity Selection Within a
Funded Year — "Select maturities…" opens the maturity-picker modal), Coupon pick (`#build-coupon`, hidden when the Maturity preference is "Last to mature" or "Select maturities…"), Allocation policy (`#rebal-alloc-policy` and its "?" help button, Rebalance only, disabled and set to "Maturity order" when the Maturity preference is "Last to mature" or "First to mature", [2.0 §Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy); "Set priority order…" opens the priority-order modal, [Priority-Order Picker](#priority-order-picker)). Brackets and Pre-ladder int. are construction policy. The items of this row are live whether or not a run has happened, as the things to set before running, and Row 3 holds the actions that wait for a run.

### Row 3 — Run + Post-Run Actions (`.card-inputs`, `margin-top: 8px`)
Contains, in order: **Run button first** (`#run-btn`, "Rebalance Ladder"/"Build Ladder" depending on
mode — deliberately the first item of Row 3, not the last item of Row 1: it's always visible, just
disabled pre-load, unlike everything after it which stays `display:none` until a run happens), then
Trade Ticket (opens the cost-breakdown modal, [4.5.3 §Trade Ticket](./4.5.3_Show_Trade_Ticket.md#trade-ticket)), **Cash Flow** (`#cash-flow-btn`, opens the payment calendar, [4.5.4 §Cash Flow Calendar](./4.5.4_Show_Cash_Flow_Calendar.md#cash-flow-calendar)), and the Duration links.

**Cash Flow is gated differently from the rest of Row 3.** It shows as soon as holdings are loaded
(`currentHoldingsArray && tipsMarketData && refCpiRows`) — it is a fact about the currently held TIPS, not a
ladder-construction result, so it does not wait for Run. Trade Ticket and Duration links stay
`display:none` until a run completes, since each depends on `buildDetails`/`rebalDetails`.
All items `align-self: flex-end`.

<a id="import-export-menus"></a>
### Import/Export Menus (`#import-menu-btn`, `#export-menu-btn` — both Row 1, side by side, Import first)

Each is a real `<button>` that toggles a floating popup (`#import-menu-list` / `#export-menu-list`) of
real `<button>` items, not a native `<select>`: Safari/WebKit does not carry a strong enough user
gesture through a `<select>`'s `change` event to open a second native picker (file-open dialog, file
save), so on WebKit the action silently never fired. A real button's `click` event preserves the
gesture on every engine. Choosing an item performs that action immediately (opening a file picker, or
triggering a download) and closes the popup — there is no "currently selected" value to leave showing,
unlike `#build-maturity`/`#rebal-alloc-policy`'s "Select maturities…"/"Set priority order…" options,
which stay selected as an ongoing state and need the click/mousedown disambiguation described in
§Priority-Order Picker below (not applicable here). Both trigger buttons share the same `.menu-select`
styling (button-themed, not `.field select`-themed) so they read as one matched pair rather than two
differently-styled controls; popup items use `.menu-dropdown`/`.menu-dropdown-item`.

The page shows no name of the loaded file. The CUSIPs and quantities of the loaded ladder are in the table.

**Import** (`#import-menu-btn`):
- **Holdings** — Rebalance only (hidden in Build, which has no holdings): opens the `#holdings-file` picker, which detects a broker file or an exported Holdings file ([4.2.1 Detect and parse holdings file](./4.2_Import_Holdings_And_DARA_Plan.md#detect-and-parse-holdings-file)).
- **DARA Plan** — both modes: opens the `#dara-plan-import-file` picker ([4.5.6 §Standalone DARA-plan file](./4.5.6_Export_Holdings_And_DARA_Plan.md#standalone-dara-plan-file)).

**Export** (`#export-menu-btn`):
- **Ladder CSV** — the rendered table ([4.5.5 §Ladder CSV](./4.5.5_Export_Ladder_Table.md#ladder-csv)), disabled until a run completes for the current mode.
- **Holdings** — the Holdings Export ([4.5.6 §Holdings Export](./4.5.6_Export_Holdings_And_DARA_Plan.md#holdings-export)), disabled until a run completes for the current mode.
- **DARA Plan** — the standalone year-to-DARA file ([4.5.6 §Standalone DARA-plan file](./4.5.6_Export_Holdings_And_DARA_Plan.md#standalone-dara-plan-file)), enabled whenever there is a per-year DARA to save, with no run required.

`_syncExportMenu()` sets the two run-gated options wherever `rebalanceRendered` or `buildRendered` changes: the mode switch, both render functions, and every reset of the output.

**Duration link button labels:** `Gap Dur` (gap/bracket duration calcs popup), `Future 30Y Dur`.

## Selection Toolbar

`#selection-toolbar` ([3.0 §Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection)) is a child of `#top-row`, after `#table-controls`, so it stays with the sticky card and cannot scroll under it as the ladder table grows. Its theme is the light theme of the table below it and not the dark form card. It is `display:none` until at least one funded-year rung is selected on the table, then `display:flex; align-items:center; gap:10px`.

The `display` change grows `#top-row` and moves the ladder table down. While the mouse button of a selecting gesture is down ([3.0 §Selecting rungs](./3.0_TIPS_Ladder_Rebalancing.md#selecting-rungs): a press-and-hold or a click-drag), the change waits for the mouseup. Shown at once, it would push the selected row down from under the stationary cursor, so that the row above would be under the cursor and the selection would look wrong. The yellow highlight of the row (background only, no layout change) applies at once.

Contents, left to right: a year-range label (`#selection-label`, for example "2028–2031 selected (4 rungs)"), a **Set DARA** number input (`#selection-dara-input`) with an Apply button (`#selection-set-btn`), an **Infer DARA** button (`#selection-infer-btn`, Rebalance only, `display:none` in Build, which has no holdings to self-finance against), and a **Clear** button (`#selection-clear-btn`).

Infer DARA solves one flat self-financing value across the selected rungs and applies it at once, with no Apply click ([3.0 §Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection)). The toolbar closes after it, as after Set DARA, and `#selection-dara-input` is cleared. The solved value is in the DARA inputs of the rung rows once they render again.

A selected group-header row has `tr.fy-group-header.selected td { background: #ffe9a8 !important }`. The `mousedown` that starts a drag calls `preventDefault()` (with `user-select: none` on the group-header cells), so that a drag across rows does not also paint the native text selection of the browser. The rule `tr.fy-group-header.selected:hover td` comes after the plain `:hover` rules and has the same specificity, so the yellow stays while the cursor is over a selected row during a drag.

There is no Undo and no Revert-to-loaded control ([3.0 §No edit history](./3.0_TIPS_Ladder_Rebalancing.md)).

## Priority-Order Picker

<a id="priority-order-picker"></a>
`#rank-picker-overlay` and `#rank-picker-modal` — the modal of the per-year override of the [Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy), opened by the "Set priority order…" choice of the Allocation policy dropdown in Row 2. It uses the mousedown, change and click handling of the "Select maturities…" choice of the Maturity preference dropdown (`#build-maturity`), applied to `#rebal-alloc-policy`. It has the same draggable and resizable modal frame (`makeDraggableResizable`, `src/modal.js`) and the same close, cancel and apply buttons as the maturity picker.

One modal covers every year in range, and it is opened from the Allocation policy dropdown only.

Each year is a row of **chips**, one per candidate or held CUSIP in the current priority order, with **◀ / ▶** buttons on each chip to reorder it (the chips lie in a row, so left and right are the directions in which a chip moves). `#rank-picker-desc` states the convention: "Left = preferred to hold/buy first. Right
= sold first if this year needs to shrink." — plus a note that under Equal split a not-held maturity
can rank ahead of a held one (2.0 §Within-Year Allocation Policy), so that isn't a bug when seen in
the picker. A year left untouched follows whatever the global policy currently produces for it
(`rankForYear`, seeded via `_rankPickerYearOrder`) — opening and Applying with no edits is a no-op.
Apply writes to `_yearRankOverrides`; picking a different named global policy clears every override
(2.0 §Within-Year Allocation Policy).

## Modal Frame Standard

Every modal with substantial content (more than a couple of short lines) uses the shared
draggable/resizable frame (`makeDraggableResizable`, `src/modal.js`) — a fixed-position,
`display:flex; flex-direction:column` panel with a `cursor:move` title bar and 8 `.resize-handle`
divs (n/s/e/w/nw/ne/sw/se). Applies to: TipsRef, the maturity picker, the priority-order picker
(both above), Trade Ticket, and the Cash Flow Calendar (4.5.3 §Trade Ticket, §Cash Flow Calendar).
`makeDraggableResizable(modalEl, titleEl, { minWidth, minHeight })` is called once per modal at
startup, alongside the others.

Small, fixed-content modals (help, account selection) are exempt — nothing in them benefits from
resizing, and a plain centered overlay is simpler.

**Resizing rules.** Dragging an edge moves that edge and holds the opposite one, including once the
size reaches `minWidth`/`minHeight`: the new `left`/`top` is derived from the size actually
applied, not from the pointer delta, so a west or north drag stops rather than sliding the modal
across the screen. The first resize also drops the content-sizing clamps, since a modal that sizes
to its content (`width:max-content` with a `max-width`, as the shared popup does) would otherwise
ignore an outward drag entirely.

**A resize may end outside the modal.** The click that follows a drag targets the nearest common
ancestor of press and release, which is the document body once the pointer leaves the modal. Any
outside-click close must therefore test where the press *started*, not where it ended, or a resize
closes the thing being resized (`src/popup.js`).

## Per-Year DARA (Table-Integrated)

The per-year DARA is entered in the ladder table, in Rebalance and in Build. A compact number input is in the group header row of each funded year, in the toggle cell after the funded-year integer ([4.5.1 §Funded Year Group Header Row](./4.5.1_Render_Ladder_Table.md#funded-year-group-header-row), [§DARA Input](./4.5.1_Render_Ladder_Table.md#dara-input)). The header of the Maturity column is the two-row stacked "DARA" over "Maturity" ([4.5.1 §Shared columns](./4.5.1_Render_Ladder_Table.md#shared-columns)). The store (`_daraByYearStore`, `getDaraByYear()`), the Set DARA and Infer DARA actions of the selection toolbar ([Selection Toolbar](#selection-toolbar)) and the DARA Plan file import and export are specified in [3.0 §Per-Year DARA (`daraByYear`)](./3.0_TIPS_Ladder_Rebalancing.md#per-year-dara-darabyyear) and [§Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection).

### Persistence rule

The values that the user edits are authoritative and survive a render:
- Every year that the user edits is stored in `_daraByYearStore` (a `Map<fundedYear, number>`).
- `_daraByYearStore` is the source of truth for the modified years, and the values of the DOM inputs are a view of it.
- `getDaraByYear()` reads `_daraByYearStore` first for each year, and the DOM input value only for a year not yet in the store.

### DARA field display

- When any stored year value differs from `_daraByYearPanelDefault`, the main `#dara` field shows **by year** (purple) in place of a number ([3.0 §Scalar DARA Field](./3.0_TIPS_Ladder_Rebalancing.md)).
- `_daraByYearPanelDefault` stays in memory, so that `_getDefaultDara()` returns it while the field shows **by year**.
- The ▲ and ▼ step buttons update `_daraByYearPanelDefault` and write the new step value to **all** store entries, because the intent is to set all years to one value.
- `updateDaraInput(force)` fills a blank field and does not replace a number that the user is typing. With `force` true it also replaces a non-empty field, and the field is then resynced to `_daraByYearPanelDefault` whenever the store is not by year. This restores the field after an Apply or an Import that makes the store flat.

### Year list

Every year in `[firstYear, lastYear]` has a group header row and a DARA input, in Build and in Rebalance:
- A funded year (actual TIPS) has no label suffix.
- A gap year (TIPS not yet issued) has the suffix `(gap)`. A custom DARA changes the Synthetic TIPS quantities and so the bracket excess.
- A Future 30Y year (after the longest-dated issued TIPS) has the suffix `(30Y)`, and exists only when `lastYear > maxTipsYear`. A custom DARA changes the hypothetical Future 30Y quantities and so the Cover Excess.

A year absent from the map takes the scalar DARA. The suffixes `(gap)` and `(30Y)` are literal text beside the DARA input (`renderGroupHeader`, `render.js`).

### The breakdown of maturing proceeds and LMI is in the popup

The breakdown of the maturing proceeds and the LMI of a year is in the Amount Before and Amount After popup ([4.5.2 §Popup Routing](./4.5.2_Show_Drill_Popups.md#popup-routing), `amtBefore`, `amtAfter`, `amount`), and the table has no inline columns for it.

The ladder table renders before Run is clicked: when holdings are loaded or accounts are selected in Rebalance, Qty Before, Cost Before and Amount Before render for every ordinary funded year ([3.0 §Before-State Preview and Bracket-Year Excess Detection](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection)).

## Collapsible Groups

### Expand / Collapse All Buttons

Two secondary buttons are in `#table-controls`: `#expand-collapse-all-btn`, labeled **Expand All** or **Collapse All** by the state of the groups, and `#expand-collapse-bracket-btn`, labeled **Expand Bracket/Cover Years** or **Collapse Bracket/Cover Years** and shown only when the table has a bracket year or a cover year. They are in `#table-controls`, a flex strip (`display:flex; gap:6px; padding:6px 16px 2px`) positioned directly above the output table divs (`#output`, `#build-output`). It's a child of `#top-row` (outside `.form-card` itself, but inside the sticky wrapper — §Selection Toolbar above explains why), so it stays pinned with the rest of the card rather than scrolling in normal page flow. `#table-controls` is hidden (`display:none`) until a result is available, then shown as `display:flex`.

Styling: the secondary-button class of the Row 3 action buttons.

### Group Header Row Visual Style

| Property | Value |
|---|---|
| Background | `#dce8e8`; a bracket year `#c0d8d8` |
| Top border | `2px solid #aac8c8`; a bracket year `#88b8b8` |
| Hover background | `#ccdede`; a bracket year `#b0cccc` |
| Selected background | `#ffe9a8` ([Selection Toolbar](#selection-toolbar)) |
| Font weight | `700` |
| Cursor | `pointer` |
| Toggle glyph | `▼` (expanded) or `▶` (collapsed), the `::before` content of the first cell; hidden on a header row with no TIPS rows (`no-children`) |
| Bracket year | `*` appended to the funded year integer |

### Child Row Visibility

When a group is collapsed (`data-expanded="false"`):
- All `.fy-child` rows with matching `[data-fy]` receive the `hidden` attribute.
- All `.acct-subrow` rows with matching `[data-fy]` receive the `hidden` attribute.
- The group header row itself remains visible at all times.

When expanded:
- `hidden` is removed from all matching `.fy-child` and `.acct-subrow` rows.
- Excess sub-rows (`.excess-subrow.fy-child`) are revealed along with the main TIPS rows — they are inseparable children of their group.
- Individual per-TIPS account expansion state (set via `style.display`) is preserved: rows that were individually collapsed before the group was collapsed remain individually hidden after expansion.

### Default State

**Bracket year and cover year groups render expanded; ordinary funded-year groups render collapsed**
(`_defaultGroupExpanded`: `data-expanded = hdr.classList.contains('bracket')`, applied to any
`fy-group-header` row with no carried-over state) — the excess holdings that make a bracket year or cover year row worth a second look are
visible at a glance without an extra click, while the common case (an ordinary single-TIPS year) stays
compact. "Expand All"/"Collapse All" (above) still act on every group regardless of this default.

### Expand/Collapse State Survives Every Re-render

Rebuilding a ladder table's `innerHTML` would otherwise reset every group back to the default above
and discard whatever the user had opened. Before the rebuild, `_captureExpandedState(tbl)` snapshots
each funded year's current `data-expanded`; after, `_restoreOrDefaultGroupsExpanded(tbl, snapshot)`
re-applies it, falling back to the normal bracket year and cover year default only for a funded year absent
from the snapshot (e.g. the year range grew).

**No change to a control on the top card collapses the table.** A change of the Maturity preference, the Allocation policy, the DARA or the year range is read in an expanded year, and collapsing the table would hide the effect. This holds for the three paths that rebuild a table: the re-run of Rebalance, the re-run of Build, and the Before-state preview before the first run ([3.0 §Before-State Preview and Bracket-Year Excess Detection](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection)). A file load renders into an empty table, which has no snapshot, so it opens at the default.

### Totals Row

The tfoot totals row is visible whether the groups are expanded or collapsed. Its values are the totals of the full ladder, excess included ([4.5.1 §Totals Row](./4.5.1_Render_Ladder_Table.md#totals-row)).
