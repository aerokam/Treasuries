<a id="form-card"></a>
## Form card

The form card is the set of controls above the ladder table, in five rows. The rows group the controls by what the holder sets: what to build, how to build it, and the actions on the result. The DARA of a range of rungs is set by selecting the rungs on the ladder table ([3.0 §Per-Rung DARA Selection](./3.0_TIPS_Ladder_Rebalancing.md#per-rung-dara-selection)).

The tab bar above the card holds, from left to right, the `← Portal` link with the title of the app, the tabs of the two modes (Rebalance and Build), and the Help button (`#help-btn`).

<a id="row-1"></a>
### Row 1: Import, Export and the ladder target

In order: **Import** and **Export** (`#import-menu-btn` and `#export-menu-btn`) side by side at the far left, then DARA, First Year (in Build the default is the Default First Year, [DD §5.1](../../knowledge/DATA_DICTIONARY.md#5.1-issuance-dependent-values)), Last Year, and Available cash (`#available-cash`, dollars, [2.0 §Available Cash](./2.0_TIPS_Ladders.md#available-cash)). The First Year and Last Year fields of the current mode are shown. Available cash is in Rebalance only. It has a `?` help button and, when the app has filled it in from the coupons already received, an amber ⚠ beside its label and an amber border on the input. Both clear when the user types a figure.

Available cash is in Row 1 because it is a figure that the ladder targets, and not a policy that governs how the ladder is constructed.

The card has no yield-source control. The source of the market data is a constant in `shared/src/market-data.js` ([4.1 §Source selection](./4.1_Load_Market_Data.md#source-selection)).

**The menus.** Each menu is a button that opens a list of buttons (`#import-menu-list`, `#export-menu-list`), and a native `<select>` is not used. Safari and WebKit do not carry the user gesture of the `change` event of a `<select>` to a second native picker (a file-open or file-save dialog), so on WebKit the action never fired, while the `click` of a button keeps the gesture on every engine. Choosing an item performs its action at once, opening a file picker or starting a download, and closes the list. The two buttons share one style, so they read as a pair. Import offers Holdings and DARA Plan ([4.2](./4.2_Import_Holdings_And_DARA_Plan.md)). Export offers Ladder CSV, Holdings and DARA Plan ([4.5.5](./4.5.5_Export_Ladder_Table.md#ladder-csv), [4.5.6](./4.5.6_Export_Holdings_And_DARA_Plan.md)).

<a id="row-2"></a>
### Row 2: Construction and computation policy

Brackets (`#bracket-mode`, Rebalance only: 2-bracket or Multi-bracket, with its own `?` help button), Pre-ladder int., Maturity preference (`#build-maturity`, [2.0 §Maturity Selection Within a Funded Year](./2.0_TIPS_Ladders.md#maturity-selection); "Select maturities…" opens the maturity-picker modal), Coupon pick (`#build-coupon`, hidden when the Maturity preference is "Last to mature" or "Select maturities…"), and Allocation policy (`#rebal-alloc-policy` and its `?` help button, Rebalance only, disabled and set to "Maturity order" when the Maturity preference is "Last to mature" or "First to mature", [2.0 §Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy); "Set priority order…" opens the priority-order modal, [4.4 §Priority-order picker](./4.4_Rebalance_Ladder.md#priority-order-picker)). Brackets and Pre-ladder int. are construction policy. The items of this row are live whether or not a run has happened, as the things to set before running, and Row 3 holds the actions that wait for a run.

<a id="row-3"></a>
### Row 3: Run and the actions on the result

In order: **Run button first** (`#run-btn`, "Rebalance Ladder" or "Build Ladder" by mode), then Trade Ticket (opens the cost-breakdown modal, [4.5.3 §Trade Ticket](./4.5.3_Show_Trade_Ticket.md#trade-ticket)), **Cash Flow** (`#cash-flow-btn`, opens the payment calendar, [4.5.4 §Cash Flow Calendar](./4.5.4_Show_Cash_Flow_Calendar.md#cash-flow-calendar)), and the Duration links `Gap Dur` and `Future 30Y Dur` ([4.5.2 §Duration Disclosure Standards](./4.5.2_Show_Drill_Popups.md#duration-disclosure-standards)). The Run button is the first item of Row 3 and not the last item of Row 1 because it is always visible, disabled before the load, unlike the items after it, which stay hidden until the condition in [Before Run](#before-run) holds. All items are aligned to the bottom of the row.

**Cash Flow is gated differently from the rest of Row 3.** It shows as soon as holdings are loaded (`currentHoldingsArray && tipsMarketData && refCpiRows`), because it is a fact about the currently held TIPS and not a result of the ladder construction, so it does not wait for Run.

<a id="before-run"></a>
**Before Run.** The controls that depend on a result stay hidden or disabled until a run completes in the mode on screen: the Ladder CSV and Holdings options of the Export menu, Trade Ticket, the Duration links, and the ladder statistics ([Row 4](#row-4)). In Rebalance the ladder table renders earlier, as soon as holdings load or accounts are selected, with Qty Before, Cost Before and Amount Before for every ordinary funded year ([3.0 §Before-State Preview and Bracket-Year Excess Detection](./3.0_TIPS_Ladder_Rebalancing.md#before-state-preview-and-bracket-year-excess-detection)). Expand All and Collapse All are available as soon as that table renders ([4.5.1 §Expand/collapse behaviour](./4.5.1_Render_Ladder_Table.md#expand-collapse-behaviour)). Build has no Before state and renders only after Run.

<a id="row-4"></a>
### Row 4: Post-run statistics

`#ladder-stats-display`: Avg Yld, Avg SA Yld, Avg Mod Dur, and Net Cash or Total Cost ([4.5.1 §Ladder stats display](./4.5.1_Render_Ladder_Table.md#ladder-stats-display)).

<a id="info-strip"></a>
### Row 5: Info strip

One row (`.card-info`), in order: `#info-source`, Term, Range, `·`, and the TIPS count. `#info-source` (`_buildRows()`) is one span holding "Trade: `<date>` · Settle: `<date>`", in both modes. The Ref CPI date is not among them: it is always the settlement date, shown right there ([3.0 §Ref CPI Date](./3.0_TIPS_Ladder_Rebalancing.md#ref-cpi-date)).

<a id="status"></a>
### Status

`#status`, inside the card below the info strip, shows the notices and the errors of a load and of a run. An error message has the class `error`.
