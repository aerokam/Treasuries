# 2.1 Export

Importing a holdings file or a DARA plan is specified in [4.2 Import holdings and DARA plan](./4.2_Import_Holdings_And_DARA_Plan.md). This file specifies the three options of the Export menu (`#export-menu-btn`, [6.0 §Import/Export Menus](./6.0_UI_Layout.md)): Ladder CSV, Holdings and DARA Plan.

## Dependencies

- [Data Dictionary](../../knowledge/DATA_DICTIONARY.md) terms: [Holdings Export](../../knowledge/DATA_DICTIONARY.md#holdings-export-format), [DARA Plan File](../../knowledge/DATA_DICTIONARY.md#dara-plan-file), [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan), [Construction Parameters](../../knowledge/DATA_DICTIONARY.md#construction-parameters)
- [4.2 Import holdings and DARA plan](./4.2_Import_Holdings_And_DARA_Plan.md): the `cusip,qty,excess` header row, the `#fundedYear,dara` block and the `#params` row written below are read back by [4.2.1](./4.2_Import_Holdings_And_DARA_Plan.md#detect-and-parse-holdings-file) and [4.2.2](./4.2_Import_Holdings_And_DARA_Plan.md#parse-dara-plan-and-parameters) on a later import

---

## Ladder CSV

The **Ladder CSV** option is enabled after a run completes for the current mode. It writes `tips-ladder-<mode>-YYYY-MM-DD.csv` (`_exportLadderCsv`, `index.html`), where `<mode>` is `build` or `rebalance`.

- The header row holds the label of every column of the table of the current mode ([5.0 §COLS](./5.0_UI_Schema.md)), with *Quantity* written as *Qty*, followed by the columns *Principal per TIPS*, *Last Cpn Per TIPS*, *LMI*, *Cost per TIPS*, *Annual Int per TIPS*, *Int from excess* and *PLI*. The first of these seven columns has an empty label and an empty value in every row.
- One row is written per detail row of the run. A row with Excess TIPS is followed by a second row with the excess figures of the table columns.
- Every cell is quoted. A quantity is written as a whole number, a yield in percent, and any other number unrounded.

## Holdings Export (Build / Rebalance)

The **Holdings** option writes a [Holdings Export](../../knowledge/DATA_DICTIONARY.md#holdings-export-format), `cusip-qty-YYYY-MM-DD.csv`, from the output of the current mode. It is enabled after a run completes for the current mode.

- The header row is `cusip,qty,excess`.
- For each detail row:
  - In Build, `qty` is `fundedYearQty` and `excess` is `excessQty`.
  - In Rebalance, `qty` is `fundedYearQtyAfter` (`qtyAfter` when absent) and `excess` is `excessQtyAfter` (0 when absent).
  - Write the row when `qty + excess` is above 0. In Build, also write the row as `cusip,0,0` when the funded year is zeroed ([Credit Pass](./2.0_TIPS_Ladders.md#credit-pass)). Rebalance writes no such row.
- When the summary holds resolved per-year DARA, append the `#fundedYear,dara` block, then the `#params` row (below).

## `#fundedYear,dara` block

The block is the marker row `#fundedYear,dara`, then one `year,amount` row for every year in `[firstYear, lastYear]`, ascending, including gap years and Future 30Y years that have no TIPS row. The amount is the per-year DARA the run used (`summary.daraByYearResolved`), rounded to whole dollars.

- The held quantities do not state the per-year DARA. A rung folds in later-maturity interest, pre-ladder interest, Cover Excess and the interest of the Simulated Outstanding Future 30Y TIPS, and a zeroed year shows `0,0`, which hides its DARA.
- With the DARA stated, a build, export, import and rebalance reproduces the ladder with zero trades for any shape: flat, edited per year, with Pre-Ladder Interest, or with Future 30Y years.
- The block states the DARA of each year and not which TIPS cover a gap year or a Future 30Y year. The Rebalance recalculates the covers by duration matching, because the yields of the day set the trades.

## `#params` row

The row `#params,key=value,...` carries the [Construction Parameters](../../knowledge/DATA_DICTIONARY.md#construction-parameters) that the DARA does not encode and that change the target ladder. The Holdings Export writes all of these keys in this order:

- **`preLadderInterest`** (`true`/`false`): with it on, [Pre-Ladder Interest](./2.0_TIPS_Ladders.md#pre-ladder-interest) zeroes the early rungs, and with it off the same years hold TIPS. Two ladders with the same per-year DARA and different Pre-Ladder Interest are different ladders.
- **`maturityPref`**: the Maturity preference ([2.0 §Maturity Selection Within a Funded Year](./2.0_TIPS_Ladders.md#maturity-selection)): `last`, `first`, `semiannual`, `all` or `select`. An import of `select` without `maturityPicks` reads it as `last`.
- **`maturityPicks`**: the picks of Select maturities ([2.0 §Picking Maturities for a Funded Year](./2.0_TIPS_Ladders.md#picking-maturities)) as `year:cusip|cusip` entries separated by `;`, ascending by year, a year with no pick written as `year:`, as in `maturityPicks=2027:912828V49|91282CEJ6;2028:9128283R9;2029:`. It is written when the picks are held, whatever the Maturity preference, because the picks are kept when a named Maturity preference is chosen.
- **`couponPref`** (`higher`/`lower`): the Coupon preference for a maturity month with two TIPS. A Rebalance writes the Coupon preference it ran with.
- **`allocationPolicy`** (`equal`/`maturity`/`saYield`): the [Within-Year Allocation Policy](./2.0_TIPS_Ladders.md#within-year-allocation-policy). Last to mature and First to mature write `maturity`. A Build with any other Maturity preference writes `equal`, because a Build splits the need of a year evenly across its maturities ([2.0 §Multi-TIPS Funded-Year Split](./2.0_TIPS_Ladders.md#multi-tips-funded-year-split)). A Rebalance writes the policy of its control. A priority order set for one year is not written.
- **`refCpiDate`** (`YYYY-MM-DD`): the Ref CPI date at which the DARA values are stated ([3.0 §DARA Reference Date](./3.0_TIPS_Ladder_Rebalancing.md)). Bare DARA values have no meaning without it.
- **`availableCash`** (dollars, rounded): [Available Cash](./2.0_TIPS_Ladders.md#available-cash), written as `0` when none.
- **`rmdCouponMode`** (`all`/`last`/`none`): the coupon-counting choice of the settlement year ([2.0 §Settlement-Year Coupon Treatment](./2.0_TIPS_Ladders.md#settlement-year-coupon-treatment)).

The importer also reads the key `rmdCashOverride` as `availableCash` ([4.2.2](./4.2_Import_Holdings_And_DARA_Plan.md#parse-dara-plan-and-parameters)). No export writes it.

## Standalone DARA-plan file

A fresh broker file, from Vanguard, Fidelity or Schwab, carries no `#fundedYear,dara` block and no other DARA data, so a Rebalance of it derives the per-year DARA from the holdings ([3.0 §Per-Year DARA from Portfolio](./3.0_TIPS_Ladder_Rebalancing.md)) and does not know the per-year DARA of an earlier session. The [DARA Plan File](../../knowledge/DATA_DICTIONARY.md#dara-plan-file) carries the per-year DARA without CUSIP rows, so it is applied to any later holdings upload, on any device.

The **DARA Plan** option writes `tips-dara-plan-YYYY-MM-DD.csv`. It is enabled whenever the per-year DARA store holds a year, with no run required. With an empty store the app reports that there is nothing to export.

- The first row is the marker `#fundedYear,dara`.
- Then one `year,amount` row per year of the per-year DARA store (`_daraByYearStore`), ascending, rounded to whole dollars. The file holds no CUSIP and no quantity.
- The last row is the `#params` row ([`#params` row](#params-row)) with every key the Holdings Export writes, taken from the controls as they stand, so a plan saved after a Build restores the Maturity preference, the Coupon preference, Pre-Ladder Interest, Available Cash and the coupon-counting choice when it is imported. The picks of Select maturities are among them.

Importing this file, or a Holdings Export for its DARA block and `#params` row, is [4.2.2 Parse DARA plan and parameters](./4.2_Import_Holdings_And_DARA_Plan.md#parse-dara-plan-and-parameters). The two files are detected differently ([4.2.1](./4.2_Import_Holdings_And_DARA_Plan.md#detect-and-parse-holdings-file)): a Holdings Export has the `cusip,qty,excess` header row and a standalone plan file has no header row and no CUSIP rows.
