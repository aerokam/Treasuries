# 4.2 Import holdings and DARA plan

**Specifies:** [4.2 Import holdings and DARA plan](/knowledge/DFD_LEVEL3_TLM_IMPORT) and the two processes it decomposes into  
**Implemented by:** `TipsLadderManager/src/broker-import.js`, `TipsLadderManager/index.html`, `TipsLadderManager/src/rebalance-lib.js`

The Import menu offers two distinct uploads, each its own file picker: **Holdings** produces a [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file), read by 4.2.1 and, when it is one this app exported, also by 4.2.2 for a trailing DARA block; **DARA Plan** produces a [DARA Plan File](../../knowledge/DATA_DICTIONARY.md#dara-plan-file), read by 4.2.2 alone — 4.2.1 never sees it.

## Processes

<a id="detect-and-parse-holdings-file"></a>
### 4.2.1 Detect and parse holdings file

**Implemented by:** `broker-import.js#parseBrokerCSV`, `broker-import.js#parseCSVLine`, and the inline Format 3/4/5 parsing in `index.html`'s `#holdings-file` change handler

Read the [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file) and produce [Holdings](../../knowledge/DATA_DICTIONARY.md#holdings), by whichever of five formats its first lines match:

- Broker keywords or columns present (`Account Number`, `Positions for account...`, a `Symbol`/`Qty` header pair): `parseBrokerCSV` reads Fidelity, Schwab or Vanguard.
  - A Schwab export's account name comes from a `Positions for account [Name] ...[Last 4 Digits]` header line preceding that account's rows, not from a column; a Fidelity export's account name comes from an `Account Name` (or `Account Number`) column instead.
  - The row states [Face Value](../../knowledge/DATA_DICTIONARY.md#face-value); divide by 1,000 and round to get [Quantity](../../knowledge/DATA_DICTIONARY.md#quantity).
  - Resolve the CUSIP: match the row's own symbol against [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) directly, or, failing that, parse a coupon-rate-and-maturity pattern (e.g. `2.125 07/15/33`) out of an `Investment Name` column and look up the CUSIP by coupon and maturity month — Vanguard's own `Symbol` column does not reliably carry the CUSIP.
  - Drop a row whose symbol does not resolve to a CUSIP in [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data).
  - Sum quantity by CUSIP within each account.
- No broker match, and the first line is `cusip,qty,excess` (case-insensitive): read a Holdings File this app exported itself. Quantity is the funded-year quantity; Excess Quantity is the gap/Future-30Y cover quantity held for that CUSIP; a CUSIP absent from [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) is dropped.
- No broker match, not this app's own export, and the first data row's third field is an integer of 2000 or more: read tipsladder.com's format — one row per funded year a CUSIP covers, no header.
  - A row whose year equals the CUSIP's own maturity year ([TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data)) adds to that CUSIP's funded-year quantity; every other row adds to its Excess Quantity.
  - Sum funded and excess quantity by CUSIP; drop a CUSIP whose maturity year is not in [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data).
- Otherwise: read the plain two-column form, one `cusip,qty` row per line, an optional header line skipped. No funded/excess split — Excess Quantity is left unset for every row.
- Drop any row whose CUSIP does not match the nine-character [CUSIP](../../knowledge/DATA_DICTIONARY.md#cusip) pattern.

Two separate implementations split a comma-separated line, neither calling into [csv.js (M1)](../../knowledge/SharedModules.md#m1) nor the other: `parseCSVLine` above (quote-aware, shared with [4.2.2](#parse-dara-plan-and-parameters) below) for the broker format, and a bare `line.split(',')` (no quote handling) inline for the other three. A real duplication, logged in [DFD_Worklist.md](../../knowledge/DFD_Worklist.md) item 27, not yet consolidated.

A broker export spanning more than one account opens the account-selection overlay instead of proceeding directly; the user's checked accounts are merged (summing identical [CUSIPs](../../knowledge/DATA_DICTIONARY.md#cusip)) into one [Holdings](../../knowledge/DATA_DICTIONARY.md#holdings) list.

**Output:** [Holdings](../../knowledge/DATA_DICTIONARY.md#holdings), to [Rebalance ladder (4.4)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER).

<a id="parse-dara-plan-and-parameters"></a>
### 4.2.2 Parse DARA plan and parameters

**Implemented by:** `rebalance-lib.js#parseFundedYearDaraBlock`, `rebalance-lib.js#parseParamsBlock`, `broker-import.js#parseCSVLine`, `index.html#_applyDaraBasis`

Scan the [DARA Plan File](../../knowledge/DATA_DICTIONARY.md#dara-plan-file), or a [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file) this app exported, for a `#fundedYear,dara` marker line and, when found, produce a [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan):

- Read every line after the marker as a `year,amount` row, using the same quote-aware `parseCSVLine` the broker format above uses, so an amount survives a round trip through a spreadsheet program (quoted thousands separators, currency symbols); a line that doesn't parse as a valid year/amount pair — the `#params` line among them — is skipped, not treated as ending the block.
- Scan the same text, independently of the block above, for a `#params,key=value,...` line and, when found, read it into the [Construction Parameters](../../knowledge/DATA_DICTIONARY.md#construction-parameters).
- Once the [Construction Parameters](../../knowledge/DATA_DICTIONARY.md#construction-parameters)' own Ref CPI date is known: restate every DARA value from it to the Ref CPI date now in effect (3.0 §DARA Reference Date).

No marker line found: produce no [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan) — a [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file) with no DARA block leaves the per-year DARA panel to mirror current holdings once [Rebalance ladder (4.4)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER) loads them (3.0 §Per-Year DARA from Portfolio).

**Output:** [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan), to [Build ladder (4.3)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER) and [Rebalance ladder (4.4)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER).
