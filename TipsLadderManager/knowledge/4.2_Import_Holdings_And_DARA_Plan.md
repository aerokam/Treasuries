# 4.2 Import holdings and DARA plan

**Specifies:** [4.2 Import holdings and DARA plan](/knowledge/DFD_LEVEL3_TLM_IMPORT) and the two processes it decomposes into  
**Implemented by:** `TipsLadderManager/src/holdings-import.js`, `TipsLadderManager/src/broker-import.js`, `TipsLadderManager/index.html`, `TipsLadderManager/src/rebalance-lib.js`

The Import menu offers two distinct uploads, each with a separate file picker: **Holdings** produces a [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file), read by 4.2.1 and, when it carries a trailing `#fundedYear,dara` marker row, also by 4.2.2; **DARA Plan** produces a [DARA Plan File](../../knowledge/DATA_DICTIONARY.md#dara-plan-file), read by 4.2.2 alone — 4.2.1 never sees it.

## Processes

<a id="detect-and-parse-holdings-file"></a>
### 4.2.1 Detect and parse holdings file

**Implemented by:** `holdings-import.js#detectHoldingsFormat`, `holdings-import.js#parseHoldingsFile`, `broker-import.js#parseBrokerCSV`, `broker-import.js#parseCSVLine`, `holdings-import.js#parseHoldingsExport`, `holdings-import.js#parseTipsladderComFormat`, `holdings-import.js#parsePlainFormat`, `holdings-import.js#maturedOnOrBefore`

Read the [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file) and produce [Holdings](../../knowledge/DATA_DICTIONARY.md#holdings): classify the file once from its structure, then parse it with the parser for that format.

- Classify the file as the first of these it matches:
  - [Holdings Export](../../knowledge/DATA_DICTIONARY.md#holdings-export-format): the first row is `cusip,qty,excess` (case-insensitive, ignoring spaces).
  - A broker export, [Fidelity](../../knowledge/DATA_DICTIONARY.md#fidelity-export), [Schwab](../../knowledge/DATA_DICTIONARY.md#schwab-export) or [Vanguard](../../knowledge/DATA_DICTIONARY.md#vanguard-export): some row has a cell `Symbol` and a cell that is `Quantity`, begins with `Qty`, or is `Shares` (case-insensitive). Fidelity, Schwab and Vanguard are one class, distinguished only by which columns the header row has.
  - [tipsladder.com Format](../../knowledge/DATA_DICTIONARY.md#tipsladdercom-format): the first data row's third field is an integer of 2000 or more. The first data row is the first row, or the second when the first row has no CUSIP in its first field.
  - [Plain CUSIP/Quantity Format](../../knowledge/DATA_DICTIONARY.md#plain-format): any other file.
- Parse a broker export:
  - Locate columns by their header text in the header row:
    - Symbol and Quantity: the two cells that made the row a header row. Both are required.
    - Account Number: a cell that contains `account number`, or is `account`. Optional.
    - Account Name: a cell that contains `account name`. Optional.
    - Investment Name: a cell that is `investment name`. Optional.
    - A later header row replaces the column positions for the rows after it.
  - For each row after a header row:
    - Skip a row shorter than the Quantity column, and a row whose Symbol is empty or contains `Total`.
    - Name its account:
      - A row whose text before `...` and digits names an account (Schwab's account row) sets the account for the rows that follow, until a row beginning `Account Total`.
      - Otherwise, when the row has an Account Number: the Account Name, when present and not `nan`, else the Account Number. Otherwise `Unknown Account`.
    - Resolve the CUSIP: the row's Symbol when [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) holds it. Failing that, when the Investment Name contains `inflation index`, parse a coupon rate and maturity from it (e.g. `2.125 07/15/33`) and look up the CUSIP by coupon and maturity month. Vanguard's Symbol column does not reliably carry the CUSIP.
    - Drop the row when no CUSIP resolves; the row is not a TIPS position.
    - Divide the row's [Face Value](../../knowledge/DATA_DICTIONARY.md#face-value) by 1,000 and round to get [Quantity](../../knowledge/DATA_DICTIONARY.md#quantity). A row with a CUSIP is never dropped for its Face Value or Quantity.
    - Sum Quantity by CUSIP within each account.
- Parse a Holdings Export: for each row after the header row, read the CUSIP, the funded quantity and the excess quantity, and set Quantity to their sum. Drop a CUSIP absent from [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) unless it has matured (below).
- Parse the tipsladder.com Format: sum funded and excess quantity by CUSIP, where a row whose year is the CUSIP's maturity year states funded quantity and any other year states excess quantity. Drop a CUSIP absent from [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) unless it has matured (below); a matured CUSIP's maturity year is its maturity date in [TIPS reference data (S2)](../../knowledge/DATA_DICTIONARY.md#s2).
- Parse the Plain CUSIP/Quantity Format: read each row's CUSIP and Quantity. Drop a CUSIP absent from [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) unless it has matured (below).
- A CUSIP has matured when [TIPS reference data (S2)](../../knowledge/DATA_DICTIONARY.md#s2) holds it with a maturity payment date on or before today, the trade date (a maturity is paid on its maturity date, or on the next bond trading day when that date is a weekend or bond market holiday, and a maturity paid today is matured). A matured CUSIP is kept, so its maturity proceeds count toward Available Cash; it is not in [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) and stays out of the ladder. A CUSIP absent from [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data) that has not matured is dropped, whether [TIPS reference data (S2)](../../knowledge/DATA_DICTIONARY.md#s2) holds it (an outstanding TIPS with no market data) or not.
- For the three non-broker formats, drop any row whose CUSIP does not match the nine-character [CUSIP](../../knowledge/DATA_DICTIONARY.md#cusip) pattern.
- For the three non-broker formats, when any CUSIP was dropped for being absent from [TIPS Market Data](../../knowledge/DATA_DICTIONARY.md#tips-market-data), show one message in the page's status element (`#status`) naming the count and the CUSIPs, in the form `<n> CUSIP(s) not in TIPS Market Data skipped: <CUSIP>, <CUSIP>`. The message is shown after the notices the load raises (the DARA and Available Cash notices), as its own row, so none displaces it. When every row was dropped, the status element shows the error `Holdings CSV has no valid data rows.` followed by the same message. A broker export shows no such message, since its rows that are not TIPS are expected.

A broker export spanning more than one account opens the account-selection overlay instead of proceeding directly; the user's checked accounts are merged (summing identical [CUSIPs](../../knowledge/DATA_DICTIONARY.md#cusip)) into one [Holdings](../../knowledge/DATA_DICTIONARY.md#holdings) list.

**Output:** [Holdings](../../knowledge/DATA_DICTIONARY.md#holdings), to [Rebalance ladder (4.4)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER).

<a id="parse-dara-plan-and-parameters"></a>
### 4.2.2 Parse DARA plan and parameters

**Implemented by:** `rebalance-lib.js#parseFundedYearDaraBlock`, `rebalance-lib.js#parseParamsBlock`, `broker-import.js#parseCSVLine`, `index.html#_applyDaraBasis`

Scan the [DARA Plan File](../../knowledge/DATA_DICTIONARY.md#dara-plan-file) or [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file) for a `#fundedYear,dara` marker row and, when found, produce a [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan):

- Read every row after the marker as a `year,amount` pair, using the same quote-aware `parseCSVLine` the broker format above uses, so an amount survives a round trip through a spreadsheet program (quoted thousands separators, currency symbols); a row that doesn't parse as a valid year/amount pair — the `#params` row among them — is skipped, not treated as ending the block.
- Scan the same text, independently of the block above, for a `#params,key=value,...` row and, when found, read it into the [Construction Parameters](../../knowledge/DATA_DICTIONARY.md#construction-parameters).
- Once [Construction Parameters](../../knowledge/DATA_DICTIONARY.md#construction-parameters)' Ref CPI date is known: restate every DARA value from it to the Ref CPI date now in effect (3.0 §DARA Reference Date).

No marker row found: produce no [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan) — a [Holdings File](../../knowledge/DATA_DICTIONARY.md#holdings-file) with no DARA block leaves the per-year DARA panel to derive its values from current holdings once [Rebalance ladder (4.4)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER) loads them (3.0 §Per-Year DARA from Portfolio).

**Output:** [DARA Plan](../../knowledge/DATA_DICTIONARY.md#dara-plan), to [Build ladder (4.3)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER) and [Rebalance ladder (4.4)](/knowledge/DFD_LEVEL2_TIPSLADDERMANAGER).
