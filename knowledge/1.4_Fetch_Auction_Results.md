# 1.4 Fetch auction results

**Specifies:** [1.4 Fetch auction results](/knowledge/DFD_LEVEL2_INGESTION)  
**Implemented by:** `scripts/getAuctions.js`, `shared/src/auction-results.js` (`mergeAuctionRows`, `fillFromTreasuryDirect`, `TD_TO_S5`)

## Dependencies

- [DATA_DICTIONARY.md](./DATA_DICTIONARY.md) — [FiscalData (E3)](./DATA_DICTIONARY.md#e3), [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15), and the data flow [Auction Results](./DATA_DICTIONARY.md#auction-results), [Auction results (S5)](./DATA_DICTIONARY.md#s5)
- `scripts/setup-windows-tasks.ps1` — the schedule of the Windows task that runs this process

---

Read the [Auction Results](./DATA_DICTIONARY.md#auction-results) that [FiscalData (E3)](./DATA_DICTIONARY.md#e3) states, fill what it states as `null` from [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15), and write [Auction results (S5)](./DATA_DICTIONARY.md#s5):

- On the first run, when [Auction results (S5)](./DATA_DICTIONARY.md#s5) does not yet exist in R2: fetch every auction FiscalData has recorded since 1980-01-01.
- On every other run: fetch only the auctions of the last 30 days, to catch one newly announced or newly settled.
- Keep every field FiscalData states for a security's auction, unfiltered — no field list narrows the columns fetched, so a column FiscalData adds later appears without a code change.
- Merge the fetched rows into [Auction results (S5)](./DATA_DICTIONARY.md#s5)'s existing rows, keyed by CUSIP and auction date:
  - A fetched row replaces an existing row of the same key, except in a column where the fetched value is `null` and the existing value is not. That column keeps the existing value, which is how a value filled from [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15) survives until FiscalData states one.
  - An existing row the fetch did not return is kept unchanged.
- [Fill from TreasuryDirect](#treasurydirect) the merged rows.
- Sort the rows by auction date, most recent first, and by security term within a date.

<a id="when-to-fetch"></a>
## When a run fetches

The Windows task runs at 11:35 AM and 1:05 PM ET, each repeated every 10 minutes for 25 minutes: 5, 15 and 25 minutes after the competitive close at 11:30 AM and at 1:00 PM ET.

An auction is *missing results* when its row in [Auction results (S5)](./DATA_DICTIONARY.md#s5) holds `null` in `total_accepted`, its auction date is within the last 30 days and not after today, and its competitive close has passed. The competitive close is `closing_time_comp` on the auction date; a row with a `null` `closing_time_comp` is missing results from the next date. Measured 2026-10-22, `total_accepted` is `null` in 1 of the 11,128 auctions dated before 2026-10-01, the 2001-09-11 auction.

A run is a *first try* when it starts less than 10 minutes after a competitive close, and a *repeat* otherwise. A run:

1. Reads S5.
2. On a repeat with no auction missing results, ends: it fetches nothing and writes nothing.
3. Fetches [FiscalData (E3)](./DATA_DICTIONARY.md#e3) and merges. When that fetch fails and S5 exists, it continues with S5's rows.
4. Only when an auction is missing results after step 3, fetches [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15) and fills.
5. Writes S5 only when its rows differ from the rows read in step 1.

A repeat therefore fetches only while an auction is missing results, and a first try always fetches FiscalData because S5 cannot show a new auction.

<a id="treasurydirect"></a>
## Fill from TreasuryDirect

[FiscalData (E3)](./DATA_DICTIONARY.md#e3) states `null` in every result column of an auction until some days after the auction, so S5 holds auctions with missing results. Measured 2026-10-21, it stated `null` for three Bill auctions held on 2026-10-19 and 2026-10-20, while [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15) stated their results. How soon after the competitive close TreasuryDirect states them is measured in [E15](./DATA_DICTIONARY.md#e15).

When [a run fetches TreasuryDirect](#when-to-fetch), read the auctions of the last 30 days from `https://www.treasurydirect.gov/TA_WS/securities/auctioned?format=json&days=30`, and for each:

- Key it by its `cusip` and its `competitiveAuctionCloseDate`, which is the auction date, as `YYYY-MM-DD`.
- When a row of S5 has the key, write into each column of the table below where the row holds `null` the value TreasuryDirect states for it. A column that holds a value is left unchanged, and a column the table omits is left unchanged.
- When no row of S5 has the key, add a row holding the columns of the table that TreasuryDirect states, with every other column `null`.
- Write a date as `YYYY-MM-DD`, and every other value as TreasuryDirect states it.
- When TreasuryDirect does not load, write the merged rows without it.

The next fetch from FiscalData that states a value for a column replaces the value written from TreasuryDirect, by the merge rule above.
