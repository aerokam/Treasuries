# 1.4 Fetch auction results

**Specifies:** [1.4 Fetch auction results](/knowledge/DFD_LEVEL2_INGESTION)  
**Implemented by:** `scripts/getAuctions.js`

## Dependencies

- [DATA_DICTIONARY.md](./DATA_DICTIONARY.md) — [FiscalData (E3)](./DATA_DICTIONARY.md#e3), [Auction results (S5)](./DATA_DICTIONARY.md#s5), and the data flow [Auction Results](./DATA_DICTIONARY.md#auction-results)
- [DataStores.md](./DataStores.md) — [Auction results (S5)](./DataStores.md#s5)
- `scripts/setup-windows-tasks.ps1` — the schedule of the Windows task that runs this process

---

Read the [Auction Results](./DATA_DICTIONARY.md#auction-results) that [FiscalData (E3)](./DATA_DICTIONARY.md#e3) states, and write [Auction results (S5)](./DataStores.md#s5): every field FiscalData states for a security's auction, unfiltered — no field list narrows the columns fetched, so a column FiscalData adds later appears without a code change.

- On the first run, when [Auction results (S5)](./DataStores.md#s5) does not yet exist in R2: fetch every auction FiscalData has recorded since 1980-01-01.
- On every other run: fetch only the auctions of the last 30 days, to catch one newly announced or newly settled.
- Merge the fetched rows into [Auction results (S5)](./DataStores.md#s5)'s existing rows, keyed by CUSIP and auction date: a fetched row replaces an existing row of the same key, and an existing row the fetch did not return is kept unchanged.
- Sort the merged rows by auction date, most recent first, and by security term within a date.

**Output:** [Auction results (S5)](./DataStores.md#s5), read directly by TreasuryAuctions.
