# 1.4 Fetch auction results

**Specifies:** [1.4 Fetch auction results](/knowledge/DFD_LEVEL2_INGESTION)  
**Implemented by:** `scripts/getAuctions.js`, `shared/src/auction-results.js` (`mergeAuctionRows`, `fillFromTreasuryDirect`, `rowFromNewTable`, `TD_TO_S5`)  
**Scheduled by:** `scripts/setup-windows-tasks.ps1`

Read the [Auction Results](./DATA_DICTIONARY.md#auction-results) that [FiscalData (E3)](./DATA_DICTIONARY.md#e3) states, fill what it states as `null` from [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15), and write [Auction results (S5)](./DATA_DICTIONARY.md#s5):

- Require S5 to exist in R2 with the columns of the table read ([FiscalData treasury_securities_auctions_v2 Reference](./AuctionsV2_Reference.md)). When S5 is missing, or lacks one of those columns, end with an error and write nothing: the job does not seed S5.
- On every run, fetch the auctions of the last 30 days, to catch one newly announced, newly settled, or corrected by FiscalData. FiscalData states the table's fields as JSON, because its CSV writes an apostrophe before a negative number.
- Keep every field FiscalData states for a security's auction, unfiltered — no field list narrows the columns fetched, so a column FiscalData adds later appears without a code change.
- Merge the fetched rows into [Auction results (S5)](./DATA_DICTIONARY.md#s5)'s existing rows, keyed by CUSIP and auction date (`comp_auction_close_date`):
  - A fetched row replaces an existing row of the same key, except in a column where the fetched value is `null` and the existing value is not. That column keeps the existing value, which is how a value filled from [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15) survives until FiscalData states one.
  - An existing row the fetch did not return is kept unchanged.
- [Fill from TreasuryDirect](#treasurydirect) the merged rows.
- Sort the rows by auction date, most recent first, and by security term within a date.
- Write S5 only when its rows differ from the rows read.

<a id="when-to-fetch"></a>
## When a run fetches

The Windows task runs at 11:35 AM and 1:05 PM ET, each repeated every 10 minutes for 25 minutes: 5, 15 and 25 minutes after the competitive close at 11:30 AM and at 1:00 PM ET. Every run fetches [FiscalData (E3)](./DATA_DICTIONARY.md#e3) and [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15). When FiscalData does not load, the run continues with the rows of S5, and when TreasuryDirect does not load, it writes the merged rows without it.

The close time of an auction is no part of the rule: the table states `comp_auction_close_time` for 2 of its 367 auctions, measured 2026-10-28.

<a id="treasurydirect"></a>
## Fill from TreasuryDirect

[FiscalData (E3)](./DATA_DICTIONARY.md#e3) states `null` in every result column of an auction until some time after the auction. Measured 2026-10-21, its `auctions_query` table, which it no longer updates, stated `null` for three Bill auctions held on 2026-10-19 and 2026-10-20, while [TreasuryDirect (E15)](./DATA_DICTIONARY.md#e15) stated their results. How soon after the competitive close TreasuryDirect states them is measured in [E15](./DATA_DICTIONARY.md#e15), and how soon the `treasury_securities_auctions_v2` table states them is [open](../research/auction-results-source/README.md#open).

Read the auctions of the last 30 days from `https://www.treasurydirect.gov/TA_WS/securities/auctioned?format=json&days=30`, and for each:

- Key it by its `cusip` and its `competitiveAuctionCloseDate`, which is the auction date, as `YYYY-MM-DD`.
- When a row of S5 has the key, write into each column of the table below where the row holds `null` the value TreasuryDirect states for it. A column that holds a value is left unchanged, and a column the table omits is left unchanged.
- When no row of S5 has the key, add a row holding the columns of the table that TreasuryDirect states, with every other column `null`.
- Write a date as `YYYY-MM-DD`, and every other value as TreasuryDirect states it.
- When TreasuryDirect does not load, write the merged rows without it.

The next fetch from FiscalData that states a value for a column replaces the value written from TreasuryDirect, by the merge rule above.

<a id="s5-names"></a>
## Names of the columns of S5

S5 holds the fields of the `treasury_securities_auctions_v2` table under its names. Before its migration it held the 114 fields of the `auctions_query` table, which FiscalData stopped updating after the auction of 2026-10-22. The conversion of the rows of that table to the new names is `convertOldRow` in `shared/src/auction-results.js`, and its basis is the field-by-field table in [research/auction-results-source](../research/auction-results-source/README.md).

**Output:** [Auction results (S5)](./DATA_DICTIONARY.md#s5), read directly by TreasuryAuctions.
