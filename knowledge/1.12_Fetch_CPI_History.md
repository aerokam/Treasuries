# 1.12 Fetch CPI history

**Specifies:** [1.12 Fetch CPI history](/knowledge/DFD_LEVEL3_INGEST_CPIHISTORY)  
**Implemented by:** `scripts/fetchCpiHistory.js`, `scripts/checkCpiReleaseDate.js`  
**Scheduled by:** `scripts/syncCpiTasks.ps1`, run by [1.16 Fetch CPI release schedule](./1.16_Fetch_CPI_Release_Schedule.md), with one trigger on each `Release Date` of [CPI release schedule (S19)](./DATA_DICTIONARY.md#s19)

Read the [Monthly CPI-U](./DATA_DICTIONARY.md#monthly-cpi-u) that [BLS (E4)](./DATA_DICTIONARY.md#e4) states, for the not-seasonally-adjusted series (`CUUR0000SA0`) and the seasonally adjusted series (`CUSR0000SA0`) alike, and write [CPI history (S8)](./DATA_DICTIONARY.md#s8):

- Skip the run when the current date, on an Eastern clock, is not a `Release Date` of [CPI release schedule (S19)](./DATA_DICTIONARY.md#s19), checked before anything is fetched.
- End the run with an error and fetch nothing when [CPI release schedule (S19)](./DATA_DICTIONARY.md#s19) cannot be read.
- Fetch BLS in ten-year windows, its free-tier limit per request, from January 1913 up through the current year.
  - Drop the annual-average row BLS reports for each year (period code `M13`) and any period code that is not a plain two-digit month, keeping one row per calendar month only.
  - A month with no value for a series (BLS states `-`, or omits it) is written blank rather than dropped, so the row still holds whichever of the two series does have a value.
- Sort the rows oldest first, by year and then by month.
- Write nothing and exit with a failure code when the latest month fetched is before the `Reference Month` of the current date's row of [CPI release schedule (S19)](./DATA_DICTIONARY.md#s19), because BLS has not yet published it. Windows Task Scheduler restarts the task every 30 minutes, up to 12 times (6 hours), on that failure code.
- Write one row per year and month, replacing the store's previous contents in full.
- Then run [1.13 Calculate daily Ref CPI](./1.13_Calculate_Daily_Ref_CPI.md), which reads the store just written.

**This is the same two series [Fetch monthly CPI (1.9)](./1.9_Fetch_Monthly_CPI.md) also reads**, fetched separately (see 1.9 for why).
