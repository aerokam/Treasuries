# 1.13 Fetch daily Ref CPI

**Specifies:** [1.13 Fetch daily Ref CPI](/knowledge/DFD_LEVEL2_INGESTION)  
**Implemented by:** `scripts/fetchRefCpi.js`

## Dependencies

- [DATA_DICTIONARY.md](./DATA_DICTIONARY.md) — [TreasuryDirect SecIndex (E2)](./DATA_DICTIONARY.md#e2), [Ref CPI (S3)](./DATA_DICTIONARY.md#s3), [Ref CPI](./DATA_DICTIONARY.md#ref-cpi), and the data flow [Daily Ref CPI](./DATA_DICTIONARY.md#daily-ref-cpi)
- [DataStores.md](./DataStores.md) — [Ref CPI (S3)](./DataStores.md#s3), [TIPS reference data (S2)](./DataStores.md#s2)
- `scripts/setup-windows-tasks.ps1` — the schedule and retry count of the Windows task that runs this process

---

## Scope

Read the [Daily Ref CPI](./DATA_DICTIONARY.md#daily-ref-cpi) that [TreasuryDirect SecIndex (E2)](./DATA_DICTIONARY.md#e2) states for one outstanding TIPS, and write [Ref CPI (S3)](./DataStores.md#s3): every calendar day that CUSIP's own SecIndex series covers, merged into the store's existing dates rather than replacing them.

**[Ref CPI](./DATA_DICTIONARY.md#ref-cpi) is market-wide.** It is identical across every outstanding CUSIP on a given date, so any one CUSIP's series states the same values as any other over the date range they share; only which dates a given CUSIP's own dated date and maturity let it cover differs.

- Read [TIPS reference data (S2)](./DataStores.md#s2) and select the outstanding TIPS with the latest maturity date, so the run has the longest possible runway before that CUSIP matures and a different one has to be selected — this selection is re-derived fresh every run, never hardcoded.
- Fetch that CUSIP's full daily series from [TreasuryDirect SecIndex (E2)](./DATA_DICTIONARY.md#e2).
- Before merging: compare the fetched series' latest date against the date [CPI history (S8)](./DataStores.md#s8)'s own latest published month implies TreasuryDirect should have reached by now.
  - If the fetched series has not yet caught up: write nothing, and exit with a failure code — TreasuryDirect lags BLS's own release by an amount this process does not know in advance, and publishing early would overwrite [Ref CPI (S3)](./DataStores.md#s3) with a series that looks complete but is missing the newest month. Windows Task Scheduler restarts the task every 30 minutes, up to 12 times (6 hours), on that failure code (`scripts/setup-windows-tasks.ps1`).
- Merge the fetched dates into [Ref CPI (S3)](./DataStores.md#s3)'s existing dates: a fetched date replaces an existing date of the same day, and an existing date the fetch did not return is kept.
  - If the merged series has a gap of more than one calendar day anywhere, or is shorter than what the store already held: write nothing and exit with a failure code, since [Ref CPI](./DATA_DICTIONARY.md#ref-cpi) is defined for every calendar day with no gap allowed. Windows Task Scheduler restarts the task the same way.
- Write the merged series ascending by date.

**A one-shot rebuild.** `fetchRefCpi.js --build` is never scheduled: it bootstraps [Ref CPI (S3)](./DataStores.md#s3) from scratch by merging two fixed CUSIPs whose combined SecIndex windows cover 1997-01-15 (the first TIPS ever issued) to present with no gap, and is run by hand only if the store ever needs to be rebuilt entirely.

**Output:** [Ref CPI (S3)](./DataStores.md#s3), the [Ref CPI](./DATA_DICTIONARY.md#ref-cpi) every app uses.
